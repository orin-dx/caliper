## 2. `fix/trust-defects-batch`

**Files:**
- New `extractor/values.rs` and `extractor/asserted.rs`.
- Edits to `extractor/mod.rs` and `extractor/visit.rs`.
- Edits to `resolver/{collected,evaluate,func,primitives}.rs` and `types/collected.rs`.
- New tests `const_value_types.rs` (8) and `asserted_props.rs` (3), plus an edit to `union_props.rs`.
- `docs/rdt-coverage.md` and a patch changeset.

**What changed:**
- `typeof X` over a literal const (`const SHOW_PARENT = 'SHOW_PARENT'`, imported or declared in a `.d.ts`) now resolves to the literal.
- `keyof typeof X` over a const object literal is now the union of its keys. A spread or computed key stays opaque, and `keyof` of anything else stays opaque.
- `true | false` and `boolean | true` become `boolean`. The existing `union_props.rs` expectation pinned `false | true`, so I changed it.
- `export default X as &lt;function type&gt;` over a component the file declares takes the function's props parameter. This adds antd Masonry's `children`.

**Checks:** 1038 Rust tests passed, and clippy, `cargo doc`, `typos` and `machete` are clean.

**Performance and oracle:**
- `just bench` is flat: Mantine 78→76 ms, Chakra 65→65 ms, memory unchanged.
- Dependency-loaded shadcn is 183→181 ms and 333→331 MiB; antd is 63→61 ms and 121→120 MiB.
- Oracle verdicts are identical to `origin/main` on both corpora. Shadcn is 7,632 shared props, 90.1% agree, 6 wrong. Antd is 3,070 shared, 93.1% agree, 0 wrong.

**Parity effect on antd:** Masonry `children` is no longer missing, and Cascader's `typeof` and `false | true` differences are gone (type differences beyond formatting 257→254).

**Not fixed, with reasons:**
- **`Segmented.options` required:** This is deliberate. `ParsedProp::new` makes any prop with a default optional by the react-docgen-typescript convention, and Segmented's body declares `options = []`. Changing it affects every defaulted prop and needs its own decision or ADR.
- **Indexed access on generic base-ui props:** `BaseUIComponentProps&lt;"div", S&gt;["onClick"]` is a mapped type with `infer` over an unbound generic, the documented type-checker gap.
- **`Modal.width` default (520):** It doesn't reproduce in isolation. A fixture with the same `const { width = 520 } = props` shape extracts the default correctly.
- **Non-literal defaults:** They are already flagged with `computed: true`, and the addon deliberately forces `computed: false` to mirror Storybook.

**Draft PR body:**
&gt; Read the value a `const` gives a prop's type. `typeof SHOW_PARENT` over `const SHOW_PARENT = 'SHOW_PARENT'` is `"SHOW_PARENT"` (antd Cascader), `keyof typeof Icons` over an object literal is its keys (antd Result), `true | false` is `boolean`, and `export default X as (&lt;T&gt;(props: PropsWithChildren&lt;P&lt;T&gt;&gt;) =&gt; Element)` takes that function's props, so Masonry gets `children`. Oracle verdicts on antd and shadcn are identical to main; `just bench` Mantine 78→76 ms, Chakra 65→65 ms; dependency-loaded shadcn 183→181 ms, 333→331 MiB. Not changed: `Segmented.options` reads optional because of the RDT convention that a default makes a prop optional (`ParsedProp::new`), and indexed access over mapped generic base-ui props is the known type-checker gap. Risks: object-literal consts are recorded as aliases (at most 128 keys, none measured as a cost); the `false | true` → `boolean` collapse changes visible output.
