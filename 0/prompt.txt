**1. JSDoc (#121)**
- **Cause:** a comment attached to any declaration that started within 120 bytes after it. In `function Badge(props: { a: string })` the first prop is resolved before the component, so it took the component's comment. The same rule let inline fields take their prop's comment, and let license headers become component descriptions.
- **Fix:** a comment now documents only the declaration directly after it. Only keywords, modifiers, decorators and other comments may sit in between, as in TypeScript.
- **Effect with default flags:** mantine 11 components change, chakra 1, shadcn 1, antd 17, spectrum 27. All the changes I checked are improvements. Diagnostic counts are unchanged.
- **Snapshots:** one description moves in `rdt_compat`, and the parse-cache golden bytes change (record shape is the same, so no schema version bump).

**3. DOM handler (#122)**
- **TypeScript's rule** (confirmed with the TypeScript checker on shadcn): when two members of an intersection declare the same prop, its type is the intersection of both. An interface's own declaration replaces the one it extends. Literal unions reduce to their common values.
- **What RDT shows:** run directly with the app's tsconfig, RDT prints only the first declaration, `ReactEventHandler&lt;HTMLDivElement&gt;`. The `string | …SVGSVGElement` in the bench results came from a different tsconfig.
- **Cause:** intersections were merged with the `extends` rule, so one declaration silently replaced the other. `React.ComponentProps&lt;"div"&gt;` is recorded as an HTML layer with no listed props, so recharts' handler was the only declaration Caliper saw.
- **Fix:** intersections now combine both types. A prop is required if any member requires it, and lists every declaration. When React's own types are loaded, the element's real attribute declaration also joins the intersection. `extends` still lets the derived declaration win.
- **Still not fixed in curated mode.** This is the CLI default and what the Vite plugin and Storybook use. Only Full mode loads React's own type declarations, and the dependency loader skips them by design (ADR 0010). So in curated mode, `ChartLegendContent.onTimeUpdate` still shows only recharts' type. In Full mode with dependencies it now shows both types intersected. Fixing curated mode would mean loading React's attribute declarations there too, which needs an ADR 0010 amendment.
- **Effect with default flags:** shadcn 1 prop (`Callout.variant` is now `"default"`, matching TypeScript), antd 2, spectrum 3; the rest are identical.
- **Effect with `--load-dependencies`:** chakra 363 components, but only the `asChild` declarations list changes (it now lists both `PolymorphicProps`). shadcn 10, antd 3, spectrum 3.
- **Speed:** chakra with dependencies went from 452 to 465 ms; the default run is unchanged. No snapshots changed.

**4. `z.infer` (#123)**

  - **Flags-off output:** it printed `z.infer&lt;schema&gt;`, because an unevaluable `typeof X` lost its `typeof`.
