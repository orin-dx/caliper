**What was built**
- `crates/core/src/dependency_types.rs` (new): the loader.
  - Demands are package names a project file uses in types. A `rayon` work queue resolves each one, follows re-exports, and parses only declaring files with Caliper's own `parse_file`. It then follows each declaration's referenced names.
  - A per-package export/resolution index is persisted in the cache dir and validated by `package.json` mtime+size. A cut re-export cycle never enters the cache.
  - The resulting `DependencyLayer` holds declaring-file data, its own `NamedTypeIndex` and `ImportResolutionMap`, the export answers, the resolutions and a dependency component value index. Each demand runs in `contain_panic`.
- **Fallback layer:** `NamedTypeIndex` and `ImportResolutionMap` fall back to the dependency layer behind an `Arc`, which watch revisions share (`named_type_index.rs`, `import_map.rs`).
- **Resolver** (`resolver/mod.rs`, `import.rs`, `precedence.rs`, `chain.rs`, `extends.rs`):
  - one shared `resolve_options` builder, with tsconfig auto-discovery, `customConditions` and `.d.mts`/`.d.cts`
  - two `resolve_dts` retries
  - resolutions and re-export answers taken from the layer
  - precedence: project declaration, then curated shortcut, then dependency declaration
  - `ComponentProps&lt;typeof X&gt;` resolved through the value index, including `import { Menu as MenuPrimitive }` followed by `MenuPrimitive.Root`
  - the ComponentMeta rule (more than 30 props) applied before resolving
- **Pipeline** (`pipeline/revision.rs`): loads before indexing. `next()` loads only demands the session hasn't seen, into a new shared layer.
- **CLI:** `--load-dependencies`, `--dependency-display`, and the env vars `CALIPER_LOAD_DEPENDENCIES` / `CALIPER_DEPENDENCY_DISPLAY`.
- **Extractor:** `import * as ns; export { ns as N }` is now recorded as a namespace re-export. radix-ui's typings are written this way.
- **Harness:** `crates/core/examples/watch_edit.rs`.

**Deviations from the plan**
- **Session memo:** implemented (`CALIPER_MEMO=1`) but not a clear win. Output is identical, but chakra goes 2.2 s → 1.8 s while memory doubles to 6.8 GB, and spectrum goes 100 → 146 ms. Copying memoized chains costs about what resolving does; resolved props need to be shared behind `Arc` instead.
- **Watch updates:** the layer is cloned when an edit adds new demands, not updated in place.
- **Not done:**
  - dependency-reason text on the unresolved diagnostics
  - project file discovery of `.mts`
  - per-declaration index summaries (whole declaring files are still parsed)
  - project barrels doing `export * from 'pkg'`
