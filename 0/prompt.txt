**PR:** https://github.com/orin-dx/caliper/pull/105 (non-draft). Branch `perf/shared-props`, base `fix/alias-display`, 5 commits.

**Design**
- **Shared props:** `ComponentEntry.props`, `ComponentEntry.notable_inherited` and `ResolvedChain` now hold `Arc&lt;ParsedProp&gt;`, so components that inherit an interface point at the same props instead of copying them. `Partial`/`Required` and plugins change a prop through `Arc::make_mut`, which copies it only if another component shares it. This changes a public Rust type, so the changeset marks core as minor and the other packages as patch.
- **Memo (`resolver/memo.rs`):**
  - **Scope:** only non-generic interfaces, keyed by interface and depth. It lives on `ResolutionContext`, which each watch revision rebuilds, so nothing survives a revision.
  - **Reuse:** each recording logs the first read of everything the result depends on: the cycle-detection sets, type parameters in scope and the component's parameter defaults. It is reused only when the current component's state answers every one of those reads the same way.
  - **Replay:** the chain itself, the state changes, the alias-display flag, watch dependencies and diagnostics.
- **One deviation from "replay diagnostics exactly":** a recording keeps each distinct diagnostic once, in the order first reported. Keeping every copy at every nesting level held 4.8 million diagnostics on chakra with dependency loading and pushed RSS to 4.7 GB. The output merges identical diagnostics anyway, and no resolver logic reads the list back (the only two reads are inside tests), so the output can't change.

**Byte-identity:** snapshots are unchanged, and the `--json` output (with `durationMs` zeroed) is identical before and after on all five corpora. With `CALIPER_LOAD_DEPENDENCIES=1` it is also identical on chakra, shadcn and spectrum.

**Tests**
- **Memo correctness:** one test resolves components on a shared context and compares each against a fresh context: entry, dependencies and distinct diagnostics. It also checks recording counts, that components share prop pointers, and that a component with its own default gets its own recording.
- **Cycle state:** another test covers a cycle reached at the same depth with and without the cycle open. No existing test caught a memo that ignored cycle state.
- **Plugins and watch:** one test checks that a plugin change stays with its component, another that a watch edit re-resolves both components and matches a cold run.
- **Fault injection:** breaking the diagnostics replay, the dependency replay, the defaults check or the cycle check each makes a test fail.
