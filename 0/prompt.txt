- **#108:** the native binding runs extraction and sessions inside worker threads, including several workers at once and a new worker after earlier ones exit.
- **#117:** adds the package `caliper-docgen-storybook`, a Storybook 11 addon. It answers each story's argTypes from a caliper session and hands anything it can't document to React's own docgen.
  - It finds the component behind `meta.component` and `meta.subcomponents` the way Storybook does, and matches a component imported through an index file by its export name.
  - It converts with `@storybook/react`'s own argTypes converter, so controls and summaries follow Storybook's rules.
  - Before each answer it checks every source file's modification time and size, so answers always include saved edits.
  - Two supporting changes: a new NAPI function returns a session's components in react-docgen-typescript's shape, and three output fixes came from diffing against React's docgen (enum `raw`, undocumented `children` kept, `() =&gt; void` callbacks).
- **#119:** the Vite plugin gains an `injectDocgenInfo` option for Storybook 10, or Storybook 11 with the docgen server off. It attaches each component's docs to the component itself, and an edit to a shared types file refreshes every affected component through hot reload.
- **#120:** removes `--format storybook`, with a breaking (minor) changeset.

Each PR has tests, changesets and passing lint and test runs; #117 and #119 also ran the integration suite on a freshly built binding.

Mid-way, two CI runs failed and I fixed them:
- **#117:** the provider loaded the native binding as soon as it was imported, which broke unit tests on CI where no binary is built. It now loads on the first request.

## What works end to end
- **Storybook 11 with the addon:** a real `storybook build` on a four-component example produced its docgen files from caliper; React's engine data is absent, which confirms caliper answered.

## Open issues
- **Quote style of string defaults** is the main remaining mismatch with React's docgen. caliper's extractor always rewrites string defaults with double quotes; keeping the source text would change caliper's main output format, so I left it.
- **Extractor bug:** a JSDoc comment on a one-line `function X(props: { a: string; … })` gets attached to the first prop instead of the component.
- **Render-prop text:** a function prop with one parameter that returns a ReactNode is printed as `=&gt; void`.
- **Index-file matching** works only when exactly one component has that export name. An anonymous default export can't receive docs in the Vite plugin mode.
- **Large repos:** the file check is a full scan per request (concurrent requests share one scan). File-watch events would make it cheaper.
- **React underneath:** when caliper answers, React's provider is not called, so React's extra engine data is absent from the output.
