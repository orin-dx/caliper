  # Prototype report: loading dependency `.d.ts` files by name
  
  **Verdict:** the main claims hold on all 8 configurations.
  - **Fewer dependency files read:** on a warm run, only the files that hold a loaded declaration are read. That is 39–833 files, versus 150–6,218 for the file-level closure.
  - **Re-export stubs never opened warm:** with the per-package index in place, warm runs open no stub files.
  - **Deterministic:** results are byte-identical across thread counts, cold vs warm index, and overlap vs sequential.
  
  Two results differ from what the design assumed:
  - **Overlap gains little:** overlapping project parsing with dependency loading saves only 0–2 ms (0–4%) over doing them one after the other.
  - **File opens are the cost driver:** on this Mac, `open()` barely runs any faster on 18 threads than on one. Embedding the declaring files' source text in the index removed every per-file dependency open and saved 3.8 ms on chakra.

  ## What was built
  `/Users/gabe/.claude/jobs/ba6a68d6/tmp/loader-proto/` is a standalone cargo workspace, about 2.6k lines. It uses the same crates as caliper (oxc 0.154, oxc_resolver 11, rayon, dashmap, rustc-hash, compact_str, mimalloc), plus postcard for the index. Release profile matches caliper's.

  |---|---|

Covered: interfaces, type aliases, classes, functions, variables (including destructured ones), enums, nested namespaces, `export default`, `export =`, and the names each declaration references (type refs, qualified `Ns.X`, `typeof`, heritage, type arguments, `import("x").Y`).   How it works:
  - **Resolution:** `oxc_resolver::resolve_dts` with a manual tsconfig. Conditions are `types, import, require, default` plus `customConditions` (`dev` for chakra, `source` for spectrum). `resolve_dts` already handles `typesVersions` and `@types` name mangling.
  - **Two resolver gaps, worked around:**
    - When a package's `exports` maps to a `.js` file, `resolve_dts` returns it instead of falling back to `@types` (react resolved to `index.js`). The prototype retries with `@types/<pkg>`.
    - It does not fall through a conditional-exports key whose target has no declaration (e.g. `@phosphor-icons` lists `"import"` before `"types"`). The prototype retries with conditions `types` + custom only.
  - **Demands:** for each package import used in a type position, the demand is (specifier, name path). Default imports become `default.X`; namespace imports `X.Y` become `Y`. `export { X } from 'pkg'` and `import X; export { X }` also count.
    - **`export * from 'pkg'` choice:** it is never a demand by itself. A project import that resolves inside the source dir is walked lazily through the project's barrels, and a package star is followed only when the name being looked up falls through to it. In practice this happened 0 times in all 5 projects.
  - **Index:** the first time a package module is looked up, its re-export graph is flattened. Discovery parses files in parallel, then a bottom-up pass over strongly connected components handles star-export cycles. Within a package the index stores the final target; across a package boundary it stores a pointer into the other package's index.
    - Persisted per package. The key is a hash of the package realpath plus the resolver config hash (tsconfig path and mtime, conditions). It is validated by `package.json` mtime + size.
    - It holds the package's specifier resolutions, but not modules whose exports are all their own declarations (those are reopened anyway). Workspace sources outside `node_modules` are never indexed; they are walked lazily on each run.
  - **Work queue:** one `rayon::scope`. Project-file tasks spawn demand tasks as soon as they finish parsing. Dependency files are claimed once through a `OnceLock` per file. A demand that needs an export map another task is still flattening parks on it and is re-spawned when it is published, so nothing blocks and there is no barrier. All results are keyed by file and declaration.
  - **Loading a declaration:** references to the same file load in place; cross-file references become new demands. Names declared nowhere are counted as global/lib references and not loaded.
  - **Optional modes:**
    - `--embed-sources` stores the source text of declaring files in the package index, so a warm run opens one file per package.
    - `LP_PERSIST=lookedup` persists only modules that were actually looked up. It only shrank the index about 15%, so it is not the default.
  
  Shortcuts and limits:
  - No `declare module 'x'` / `declare global` / module augmentation, so `node:fs` and similar fail.
  - `/// <reference>` directives are not followed.
  - No `import x = Ns.Y` aliases.
  - When star exports conflict, the first one wins; TypeScript would report an ambiguity.
  - Whole interfaces are loaded with every member's references; there is no per-member laziness.
  - Name resolution is by name with namespace scopes, not a full scope analysis.

  ## What this proves and what it does not
  Proven:
  - Name-driven loading cuts dependency files read by 47–89% versus the closure on a warm run.
  - The per-package export index removes all stub opens and resolver traffic inside dependencies.
  - Parking on an export map that is still being built gives a work queue with no barrier and no deadlock, and the results are deterministic.
  - Incremental demands are cheap enough for watch mode.
  
  Not proven:
  - Turning loaded declarations into PropTypes (stage 2): no generics instantiation, `Omit`/`Pick`, or conditional types.
  - Agreement with the TypeScript checker beyond these spot checks.
  - Whether loading whole interfaces over-loads; per-member laziness was not tried.
  - File-open costs on Linux or Windows.
  - An RSS-optimised design.
  
  ## Surprises
  1. File opens on macOS barely parallelise, so the number of files matters more than bytes or overlap.
  2. The two `oxc_resolver` `resolve_dts` gaps above; without the @types retry, react resolved to `index.js` (no types).
  3. Icon packages dominate cold cost and index size: phosphor, tabler, hugeicons and lucide have 1,500+ exports. Parsing lucide's 2 MB `.d.ts` to load one icon sits on the critical path.
  4. The project-barrel `export * from 'pkg'` case never occurred, yet chasing internal names cost thousands of lazy walks (spectrum: 12k internal demands).
  5. Modules whose exports are all their own declarations made the index about 30% bigger for no benefit, so they are no longer persisted.
  
  ## Recommendations for the real implementation
  - **Index format:**
    - One file per (package realpath, resolver-config hash); format version in the header.
    - Validate by `package.json` mtime + size. Patch-package edits files without touching `package.json`, so also hash the lockfile or the `patches/` dir.
    - Contents: a path table (indices, not strings), flattened export maps only for modules with re-exports, the package's specifier resolutions, and cross-package targets stored as pointers rather than copied.
    - Write it off the critical path.
    - Use a format that supports lookup without decoding the whole file (sorted name table or zero-copy). Decoding the index was about 8 ms of CPU summed across threads on shadcn, dominated by icon packages.
  - **Next step to prototype:** store per-declaration summaries (byte range + references) of declaring files in the same package file instead of whole source text. Warm runs would then do one open per package and no whole-file parse of 2 MB `.d.ts` files. Embedding whole sources already showed a 22% warm win on chakra; the per-declaration version is unmeasured.
  - **Work queue:** reuse the shape as is (spawn per demand, claim per file, park on an in-progress export map, publish and respawn). Run it inside the existing `contain_panic` boundary (ADR 0005), and emit a `Diagnostic` for every unresolved demand reason.
  - **Upstream:** report the two `resolve_dts` gaps to oxc_resolver; keep the retries until fixed. Add ambient `declare module` support for `node:*`.
  - **Where it slots into caliper:**
    - In `pipeline/revision.rs` `resolve_cold`, replace the project `par_iter` parse with the scope above. Each `SourceData` emits its demands (it already has imports and type references).
    - Merge the loaded declarations into `GlobalSourceData` before `NamedTypeIndex::build` and `ResolutionContext::new_with_cached_ambient_global_files` (lines 229–237). This subsumes the Phase 3.5 whole-file `@types/react` merge.
    - `WatchSession::update_file` needs the same demand diff; this is a sibling path and needs a parity test.
    - This replaces the msgpack `DtsCache` for dependencies, so it needs a new ADR.
