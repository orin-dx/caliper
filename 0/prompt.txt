**#114 – `ensureFresh` for hosts with no file watcher, such as a Storybook worker.**
- **How it works:** `WatchSession::ensure_fresh()` in core, and `ensureFresh(sessionId)` in NAPI, check what the session read: source files, the directories they live in, and config files. A config change rebuilds the session. Created, deleted and edited files are applied as one update. When nothing changed, the revision stays the same.
- **Detecting changes:** it compares modification time and size. For anything modified in the last 2 seconds it also compares a hash of the contents, because some filesystems record times too coarsely to tell two edits apart.
- **Cost:** sessions that never call it pay nothing.
- **Tests:**
  - an edit, a new file and a deletion each produce the same update as `update_file`, and the result matches a fresh full extraction;
  - a tsconfig change gives the same update as `update_file`;
  - nothing changed, and before initialization;
  - the binding's error for an unknown session and its exact JSON;
  - turning off directory rescanning makes the new-file test fail.
- **Results:** the workspace suite passed 729/729, binding 16/16, TS unit 41/41, integration 5/5, and `just lint doc-check machete typos` was clean. **#116 – reproducible performance scorecard and CI gates.**
- **Script:** `scripts/scorecard.py` (Python stdlib) fetches the five corpora at pinned commits. For each it records lines of code, components, props, unresolved types, wall time, the tool's own reported time, and peak memory. `scripts/scorecard-rdt.mjs` times react-docgen-typescript on the same files.
- **Workflow:** `scorecard.yml` runs weekly and by hand. It builds main and the branch in the same job and times them alternately. It fails if the branch is more than 1.1× slower than main on any corpus, or less than 10× faster than react-docgen-typescript.
- **Scaling test:** rather than gating on the size model, it fails if extracting two copies of Mantine takes more than 2.2× as long as one. The model (t ≈ 6.4 ms + 0.13 ms/kLOC + 3.8 ms/kprop) is reported but not gated: it was within 2× on every corpus but ranged from 0.45× to 1.6×, so a gate on it would flake.
- **No committed baseline:** react-docgen-typescript takes 1 to 2 s per corpus, so CI times it live.
- **Local results:** 34–81 ms per corpus, 17–39× faster than react-docgen-typescript, scaling 1.77×, all gates pass. Documented in `docs/performance.md`.
