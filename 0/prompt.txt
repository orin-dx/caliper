### 3. `DocgenPlugin` trait — `crates/core/src/plugin.rs` (full file, 189 lines)

## 3. Async Content-Length framing

Generic over `tokio::io::AsyncBufRead`/`AsyncWrite` (used both by `client.rs` over `ChildStdout`/`ChildStdin`, and by `fake_tsc.rs` over `tokio::io::stdin()`/`stdout()` — same code, no drift between what the real client parses and what the fake server emits):

pub fn check_frame_len(len: usize, cap: usize) -&gt; Result&lt;(), TscClientError&gt;;

## 4. Request/response correlation

Standard tokio pattern, `dashmap` (already a workspace dep) over a single `Mutex&lt;HashMap&gt;` for the pending-request table:

```rust
#[derive(Clone)]
pub struct Client(Arc&lt;ClientInner&gt;);

struct ClientInner {
    stdin: tokio::sync::Mutex&lt;tokio::process::ChildStdin&gt;,   // serializes concurrent writers
    pending: DashMap&lt;u64, oneshot::Sender&lt;Result&lt;TaggedResponse, TscClientError&gt;&gt;&gt;,
    next_id: AtomicU64,
    next_seq: AtomicU64,                                      // wire-arrival order stamp, see §5 stale notification
    notifications: Mutex&lt;Option&lt;mpsc::UnboundedReceiver&lt;Notification&gt;&gt;&gt;, // taken exactly once
    child_exited: watch::Receiver&lt;Option&lt;std::process::ExitStatus&gt;&gt;,
    shutdown_requested: AtomicBool,
}
```

One background reader task (spawned at connect) owns `ChildStdout`, loops `transport::read_frame`, and dispatches by shape: has `"id"` and (`"result"` or `"error"`) → pop `pending`, complete the oneshot; has `"method"` and no `"id"` → push onto the notifications `mpsc`; unparsable body → log + drop (recoverable, see §5). On a fatal transport error (malformed header, oversized, EOF, crash), the reader task calls one `fail_all_pending(err)` cleanup path that drains `pending` and drops the notifications sender (closing that channel signals "no more notifications" to a polling caller without a separate flag).

`notifications()` is single-consumer by design (`Client::take_notifications(&amp;self) -&gt; Option&lt;mpsc::UnboundedReceiver&lt;Notification&gt;&gt;`, `None` after the first call) so `Client` itself stays cheaply `Clone` for concurrent request-issuers.

## 5. Supervisor — one decision per Lifecycle-gate item

- **Missing binary**: `Command::new(tsc_path).spawn()` failing (ENOENT) → `TscClientError::SpawnFailed { path, source }` with a config.rs-style hint ("install `typescript@next` or pass an explicit path"). No retry — retrying a nonexistent binary is pointless.
- **Unsupported version**: checked from `package.json` on disk, *before* spawning (cheapest path per the doc: "no protocol round-trip needed"). Given `tsc_path` (e.g. `.../node_modules/typescript/bin/tsc`), read `tsc_path.parent()?.parent()?.join("package.json")`, parse `"version"`, compare against a compiled-in pinned allowlist. Mismatch → `TscClientError::UnsupportedVersion { found, expected }`; unreadable/unparsable → distinct `VersionCheckFailed`. This ordering means version-check failures never pay a process-spawn cost and are trivially separable from `SpawnFailed` in tests.
- **Timeout**: `Client::request(method, params, deadline: Duration)` wraps the oneshot await in `tokio::time::timeout(deadline, rx)`. No crate-wide default for calls (Cost table shows call costs vary ~1ms to ~400ms) — deadline is an explicit per-call argument; only the internal handshake/version-check path gets a generous built-in constant (`DEFAULT_HANDSHAKE_TIMEOUT = 10s` against a measured 33–72ms). On elapse: remove the pending entry (a late response after timeout is a no-op send) and return `TscClientError::Timeout { method, after }`.
- **Crash**: two converging signals — (a) a dedicated task does `child.wait().await` once and publishes via `watch::Sender&lt;Option&lt;ExitStatus&gt;&gt;`; (b) the reader task's own read loop hits EOF/IO error. Whichever fires first calls `fail_all_pending(Crashed { status })`; the other is a no-op (oneshots already completed). A request whose write succeeded but whose child died before answering surfaces `Crashed` immediately rather than waiting out its full deadline.
- **Restart storm**: bounded window+count, not unlimited retry. `MAX_RESTARTS = 3` within `RESTART_WINDOW = 60s`, backoff `200ms, 400ms, 800ms` (capped `BACKOFF_MAX = 5s`) between attempts. Exceeding the cap moves the `Supervisor` to a terminal `Failed` state — every subsequent call short-circuits with `TscClientError::RestartStormDetected { attempts, window }` without touching the process again. Auto-restart only keeps the *process* available for the *next* call; it never silently replays a request lost to a crash (that request already got `Crashed` — retry policy for a specific call is the caller's decision, not this crate's, since blind retry of a non-idempotent RPC is unsafe).
- **Malformed or oversized frame**: reuses `transport::read_frame`'s typed errors. A malformed **header** block (no/unparsable Content-Length) is fatal for the session — the next frame's byte offset is unknowable, so it's routed through the same `fail_all_pending` path as a crash. A malformed **JSON body** (full length known via a valid Content-Length) is recoverable — log + drop that one frame, session stays alive (mirrors lsp.rs's own header-vs-body asymmetry). Oversized frame is fatal, checked before allocation, cap configurable via `SupervisorConfig::max_frame_bytes` (default `DEFAULT_MAX_FRAME_BYTES`) so tests don't need to push 16 MiB over a pipe.
- **Partial project failure**: this crate does no batching/aggregation — `Client::request` is per-call, returns `Result` per call. A caller driving many files/components issues many concurrent `request()`s and collects `Vec&lt;Result&lt;..&gt;&gt;` itself. The crate's job is only to make per-call failure modes distinguishable: a JSON-RPC `error` object in an otherwise well-formed response → `TscClientError::RpcError { code, message, data }`, scoped to that one request only, proven not to affect a concurrently in-flight sibling. Session-wide failures (`Crashed`, `MalformedFrame`, `RestartStormDetected`) are the "whole batch fails" case; `RpcError` is the "this one item fails" case — that distinction is what a future merge step needs.
- **Shutdown reaping**: `pub async fn shutdown(self) -&gt; Result&lt;(), TscClientError&gt;` — sets `shutdown_requested` first (so the exit-watcher doesn't report a clean exit as a crash), drops `ChildStdin` (EOF), races `tokio::time::timeout(SHUTDOWN_GRACE = 2s, child.wait())`; on timeout, `child.kill()` then **unconditionally** `child.wait()` afterward so the child is always reaped, never a zombie. `Drop` is a non-blocking best-effort `child.start_kill()` + `tracing::warn!` only (async work can't run in sync `Drop`) — documented as a fallback, not the primary path; tests exercise `.shutdown()` directly for the hard reaping guarantee.
- **Stale notification**: freshness tracked by a monotonic `next_seq: AtomicU64` stamped by the reader task in true wire-arrival order (not issue order, not wall clock). `Client::request` returns `TaggedResponse { value, seq }`. A caller comparing "seq an update was acknowledged at" vs "seq a later query's answer arrived at" can mechanically tell whether that answer could possibly reflect the update (`answer.seq &gt; update_ack.seq`) — this is the concrete, testable slice of freshness tracking buildable without the real `updateSnapshot` wire shape (which was still churning per the doc's "Churn" section).

## 6. Error type

```rust
// error.rs
#[derive(Debug, thiserror::Error)]
pub enum TscClientError {
    #[error("tsc binary not found at {path} — install `typescript@next` (npm i typescript@next) or pass an explicit path ({source})")]
    SpawnFailed { path: camino::Utf8PathBuf, #[source] source: std::io::Error },

    #[error("tsc at {path} reports version {found:?}, not pinned (expected one of {expected:?})")]
    UnsupportedVersion { path: camino::Utf8PathBuf, found: String, expected: &amp;'static [&amp;'static str] },

    #[error("could not determine tsc's version at {path}: {reason}")]
    VersionCheckFailed { path: camino::Utf8PathBuf, reason: String },

    #[error("request {method:?} timed out after {after:?}")]
    Timeout { method: String, after: std::time::Duration },

    #[error("tsc exited unexpectedly (status: {status:?})")]
    Crashed { status: Option&lt;std::process::ExitStatus&gt; },

    #[error("tsc restarted {attempts} times within {window:?}; treating as permanently failed")]
    RestartStormDetected { attempts: u32, window: std::time::Duration },

    #[error("oversized frame: declared Content-Length {declared} exceeds the {cap}-byte cap")]
    OversizedFrame { declared: usize, cap: usize },

    #[error("malformed frame: {reason:?}")]
    MalformedFrame { reason: MalformedFrameReason },

    #[error("tsc returned a JSON-RPC error (code {code}): {message}")]
    RpcError { code: i64, message: String, data: Option&lt;serde_json::Value&gt; },

    #[error("session already shut down or permanently failed")]
    SessionClosed,

    #[error("I/O error writing to tsc: {0}")]
    Write(#[source] std::io::Error),
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum MalformedFrameReason { NoContentLengthHeader, UnparsableContentLength, TruncatedBody }
```

Every one of the 9 gate items maps to a distinct `matches!`-able variant (partial-project-failure splits across `RpcError` (per-call) vs `Crashed`/`RestartStormDetected` (session-wide); shutdown reaping and stale notification are behaviors/APIs, not error variants).

## 8. Fake-tsc test harness

`crates/tsc-client/tests/bin/fake_tsc.rs`, a tiny tokio async `[[bin]]` (not a shell script — Windows CI, per cargo-deny's Windows targets in `Cargo.lock`), reading scenario selection from `FAKE_TSC_SCENARIO` (env var, matching config.rs's env-over-argv precedent for anything test/caller-controlled). Built against this crate's own `transport::{read_frame, write_frame}` for all "valid frame" scenarios, so the fake server can't drift from the real client's wire format; "bad frame" scenarios intentionally bypass `write_frame` and hand-write raw bytes.

Scenarios: `never_respond`, `hang_after_n:&lt;N&gt;`, `exit_after:&lt;N&gt;:&lt;code&gt;`, `garbage_bytes`, `bad_content_length`, `oversized_frame:&lt;N&gt;`, `truncated_body`, `echo` (baseline, honors `params.fail` to emit an `error` object), `reorder_ack` (answers request 2 before request 1), `shutdown_slow:&lt;ms&gt;`.

Test files, one per gate item (§5 items 1–9), each spawning `env!("CARGO_BIN_EXE_fake-tsc")` via a shared `tests/common/mod.rs` helper and asserting on the specific `TscClientError` variant (or, for shutdown reaping, on wall-clock bound + process liveness; for stale notification, on `seq` ordering). `lifecycle_malformed_or_oversized_frame.rs` covers header-malformed, body-malformed(none needed, recoverable path can live as a unit test in framing.rs), and both oversized-rejected and exactly-at-cap-accepted in one file since they're one gate item per the ADR's literal phrasing.

  Supervisor restart/liveness read `Client::closed()` only (no `is_finished`, no `Crashed | Write` matching), so NEW-1 cannot recur. `shutdown()` returns the reaped `ExitStatus` (covers C-crashed-status).
  
  ## Coverage gap
  No persisted arch model (docs/architecture/model.json absent; docs/architecture/README.md does not cover crates/tsc-client). audit-architecture should bootstrap it after implementation with the invariant "only the writer task holds ChildStdin; a session closes once, with a reason".
  
  ## Design questions for the user (defaults already written into the criteria)
  - Q1 Write-queue capacity: bounded `mpsc` of 16 whole frames as a `const`, or a `SupervisorConfig` field? (Unbounded would let memory grow against a non-reading child.)
  - Q2 Shutdown: fail in-flight requests immediately with `SessionClosed` (default), or let responses land for up to `SHUTDOWN_GRACE` first?
  - Q3 `shutdown(self) -> Result<ExitStatus, _>` (default), or keep `Ok(())` and delete the always-`None` `Crashed.status` field?
  - Q4 Restart on every closed reason: a child that always emits a bad header burns the 3-restart budget in 3 calls (AC-10). Confirm, or treat `MalformedFrame`/`OversizedFrame` as non-restartable?
  - Q5 Stale clone after restart: returns the old session's true reason (default) vs. remapped `SessionClosed`?
  
  ## ADR
