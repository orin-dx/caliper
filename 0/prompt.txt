  ## TS 7 / 7.1 research for the semantic backend (2026-10-21)
  
  **Bottom line:** the beta API has every checker call Caliper's algorithm needs. The serious risk is that TypeScript does not support the wire protocol a Rust client speaks. RDT has no TS 7 path yet. Native TS should cut Caliper's cold-start speed lead to roughly 8x and mostly close the incremental gap.

  ### 1. TypeScript 7 / 7.1 (confirmed unless marked)
  
  **Release dates**
  - 7.0: RC 2026-06-18, stable `7.0.2` on 2026-07-08 (npm). About 10x faster than TS 6. It has no programmatic API.
  - 7.1 beta: blog post and npm `7.1.0-beta` both 2026-10-20 ([blog](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/)).
  - The iteration plan ([#63703](https://github.com/microsoft/TypeScript/issues/63703)) said beta 10-06, RC 11-10, stable 11-24. On Sep 1 Rosenwasser said the beta would slip about 2 weeks, with RC/stable "details to come". The blog says the RC is "about a month from now", so (inferred) RC is late November and stable probably December.
  
  **Entry points**
  - The beta's exports map has `sync`, `async`, `fs`, `path`, `proto`, `ast`, `ast/{is,factory,clone,utils,scanner,visitor}` and `vscode`.
  - The blog documents only `sync`, `async`, `fs`, `ast`, `ast/is` and `ast/factory`. Treat `proto` as less committed.
  - The `/unstable` prefixes are gone.
  
  **Transport** (from `dist/api/options.js`, `syncChannel.js`, `async/client.js`)
  - The clients spawn `tsc --api [--async] --cwd <dir> --useCaseSensitiveFileNames=<bool> [--runExternalCode] [--timing] [--callbacks=…]`.
  - Sync client: msgpack over stdio pipes (`--pipe` named pipe on Windows).
  - Async client: vscode-jsonrpc over stdio, or over a Unix socket.
  - There is a socket mode (`LSPConnectionOptions`) plus `getCurrentLanguageServerSnapshot`. Inferred: a client can attach to an already-running language server.
  - `InitializeResponse` has only `caseSensitivity` and `currentDirectory`, so there is still no version handshake.
  - There is no native library; a non-JS host must speak this protocol.
  
  **Checker surface**
  - 178 methods (the repo doc says 157).
  - Everything the algorithm uses is there: `getSymbolOfSourceFile`, `getExportsOfModule`, `getTypeOfSymbol(AtLocation)`, `getSignaturesOfType`, `getResolvedSignature`, `getReturnTypeOfSignature`, `get(Apparent)PropertiesOfType`, `getBaseConstraintOfType`, `typeToString`, `getDocumentationComment`, `getJsDocTags`.
  - New and useful for batching: `batchRequests` (paged, `maxResponseBytesPerPage`), and plural forms such as `getTypesOfSymbols`, `getTypeAtLocations`, `getSymbolsAtPositions`.
  - Also present: conditional and mapped type accessors, and `getContextualType`.
  - Positions are UTF-16. Snapshots are released explicitly (`release`) and source files are retained or released through leases. The blog warns that undisposed snapshots leak on the Go side.
  
  **Stability** ([#64709](https://github.com/microsoft/TypeScript/issues/64709), Andrew Branch, 2026-10-09)
  - "After 7.1 stable, we intend to keep all API changes backward compatible during the 7.x series, from the perspective of a TypeScript consumer using our provided API client."
  - "The client/server API communication protocol is an implementation detail and might change in minor version releases."
  - Watch, incremental and build-orchestrator APIs are not stable in 7.1.
  - Breaking changes before stable only "if absolutely needed."
  
  **Performance (blog)**
  - 7.1 beta checks 1.2–1.9x faster than 7.0 (4 checker threads, `--noEmit`) and uses 16–50% less memory.
  - Third-party IPC measurements ([websmith #199](https://github.com/quatico-solutions/websmith/pull/199), 10-15): cold start 43 ms; createProgram plus checks takes 0.34x the time of in-process TS 6.0.3. The p95 tail ratio failed, but in-process TS 6.0.3 failed it too.
  
  ### 2. Docgen tools on TS 7
  
  - **RDT upstream:** last release 2.4.0 (2025-06-10). It crashes on TS 7 ([vite-plugin #81](https://github.com/joshwooding/vite-plugin-react-docgen-typescript/issues/81)). A fork ([cyberuni #1](https://github.com/cyberuni/react-docgen-typescript/issues/1), 09-04) plans a 7.1 port, but has no code yet.
  - **Storybook:**
    - [#35792](https://github.com/storybookjs/storybook/issues/35792): on 08-08 a contributor said Storybook "doesn't support TypeScript 7". It was closed 10-14 by a fail-fast guard.
    - [#36771](https://github.com/storybookjs/storybook/pull/36771) was closed unmerged on 10-21: "We are not going to teach Storybook how to find a TypeScript compiler API." The plan is to offer an alias from `typescript` to `@typescript/typescript6` at init and upgrade. So Storybook's RDT path stays on the JS TS 6 checker for now.
  - **react-docgen (Babel)** is unaffected and remains Storybook's default.
  - **TypeDoc** ([#3098](https://github.com/TypeStrong/typedoc/issues/3098)): its port to the 7.1 API had about 70–80% of tests passing in August and now targets the 7.1 RC. It is blocked on missing APIs.
  - **Vue:** vue-component-meta is waiting for the 7.1 API and content mappers (secondary source only).
  - No benchmark exists of any docgen tool running on a native checker.
  
  ### 3. Prior art for "fast structural pass plus checker fallback"
  
  - **oxlint + tsgolint** is the closest match: Rust handles discovery and syntactic rules, and a Go binary builds real programs on typescript-go. It reached stable v7 on 2026-09-11, tracks TS 7.0.2, and claims 12–18x over ESLint (vendor numbers) ([InfoQ](https://www.infoq.com/news/2026/09/tsgolint-oxlint-typescript/)). It links typescript-go internals rather than the API (per ADR 0006; InfoQ doesn't say).
  - **Biome** does its own partial type inference with no tsc. Its `noFloatingPromises` caught about 75%, then 85%, of typescript-eslint's cases (2025) ([Biome v2](https://biomejs.dev/blog/biome-v2/)). That is evidence of the ceiling for a structural-only approach.
  - I found no docgen tool built on `isolatedDeclarations`.
  
  ### Implications for Caliper
  
  1. **Process model:**
     - A Rust client speaking the protocol directly is officially unsupported, and minor releases may break it. Only the JS client carries the 7.x compatibility promise.
     - Keep the exact-version pin and startup check (ADR 0006). Generate or verify message types from `proto.generated.d.ts`, and run a CI job against `typescript@next`.
     - Promote the Node sidecar from last resort to a planned second transport. After 7.1 stable it is the only stable surface.
  2. **Which queries:** collapse the per-component chain into `batchRequests` and the plural methods; the 55-file run currently takes 937 requests. ADR 0007's discovery of wrapper calls needs only `getResolvedSignature` and `getReturnTypeOfSignature`, both present.
  3. **When to trigger:** ADR 0007's incomplete-only trigger fits. The fixed cost is spawn plus program build, so start `tsc` early, as the design doc already proposes.
  4. **What to cache:**
     - Key semantic results on file content plus dependency hashes, the exact TS version and the tsconfig. `typeToString` output varies between versions.
     - Release snapshots and source-file leases on every path, including errors.
     - Don't depend on the watch/incremental APIs; `snapshot.update({fileNotifications})` is the documented route.
  5. **Speed erosion (inferred from Caliper's own numbers):**
     - On the 55-file corpus, the algorithm on native 7.1 took 385 ms, versus 955 ms for in-process RDT and 50 ms for Caliper's structural pass. A native RDT would cut Caliper's cold-start lead from about 19x to about 8x.
     - Incrementally, the native path takes about 3.3 ms (0.5 ms update + 2.8 ms query) against Caliper's 1.75–2.1 ms. That gap mostly closes.
     - Today no RDT runs natively and Storybook is pinning TS 6, so the lead holds in the near term.
     - Longer term, Caliper's position shifts from raw speed to: no TypeScript toolchain or process by default, deterministic output, and checker accuracy only on request.
