On AST and typing vs special cases: it's a mix. The core is structural, but a layer of name-based rules sits around it.

Decided from structure:
- What counts as a component: JSX, hooks or the shape of what it returns (#71), not library names.
- Wrapper props: read from the call's type arguments and payload type, not from a list of wrapper names.
- Type arguments and key sets: type arguments are typed values (the old string parsers are gone), and Pick/Omit keys are computed from those types.
- Everything from this round (#75–#82) is general machinery and adds no special cases:
  - watch revisions with recorded dependencies
  - one entry per diagnostic
  - the cache fingerprint
  - the speed-ups
  - streamed JSON output
  - generic-alias substitution, which on its own cut leaked parameter names on Mantine from 25,624 to 72

Some of this is fair, because there's no type checker: React and the TypeScript lib types are a fixed vocabulary. Most of it could be structural instead:
1. The silence list becomes "the name is declared in a TypeScript lib or @types file". We already load those files.
2. The wrapper-name rules become "the argument shows render evidence", which the generic wrapper path already does.
3. The library shortcuts move behind the DocgenPlugin hook, so the core holds no library names.
4. A small evaluator for keyof and mapped types over a known, finite set of keys replaces the per-name utility handling. It would also cover Record and many of the remaining opaque types.
5. The React tables come from @types/react when it's installed.
