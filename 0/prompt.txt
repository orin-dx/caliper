**Location:** `crates/core/src/pipeline/revision.rs:572`

With automatic tsconfig discovery, a bare alias imported under a nested config can reach `resolve_file` during dependency loading (`crates/core/src/dependency_types.rs:533`, `crates/core/src/resolver/import.rs:302–312`). If that nested config references the governing `tsconfig.json` by filename, oxc caches the governing config without loading its own references (`tsconfig_resolver.rs:247–265`); the later validation on the reused resolver (`crates/core/src/resolver/mod.rs:373–374`) accepts that cached entry and no longer warns if the governing config has a missing reference.
