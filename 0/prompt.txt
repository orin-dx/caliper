  ## B. Design improvements, ranked
  
  **1. Replace string type arguments with structured data (fixes D1, D2; unblocks RC2/RC3).** Effort M. Risk medium: it changes the cache wire format, so bump `CACHE_SCHEMA_VERSION` to 5.
  - The planned object-literal type arguments (`Factory<{props: P}>`) cannot survive `Vec<String>`. This is the main blocker for the planned feature.
  - `Pick`/`Omit`/`Partial`/`Required`/`Readonly` knowledge is also spread over four places: `extractor/alias.rs:19`, `chain.rs:65-95`, `substitute.rs:291-312` and `resolver/mod.rs:94`. A `UtilityKind` enum would unify them.
  ```rust
  // before: collected.rs:725, ExtendsRef 616/620/630
  pub props_type_args: Vec<String>,
  // after (CollectedType is already Serialize/Deserialize)
  pub props_type_args: Vec<CollectedType>,
  // chain.rs:113-120 then calls resolve_collected_type(&arg, ..) directly; delete Raw round-trip and raw_arg_to_collected_type
  ```
  - Keep `CollectedType::Raw` only for true unknown syntax, and emit a diagnostic whenever it is hit.
  - Speed: this removes `to_raw_string` + `format!` + `join` + re-guess on every generic reference, so it should be neutral to positive.
  
  **2. Make detection classify once and carry its reason.** Effort S to M. Risk low. This is root-cause cluster 2.
  - `visit.rs:229-234` chains four `Option`-returning `try_*` methods with `.or_else`. A fifth, `try_rename_identifier_wrapped_component`, has a side effect (it pushes a mapping) inside an `if` condition at `visit.rs:238-239`. Each detector re-peels the same expression.
  - `record_skip` discards its `Span` (`extractor/mod.rs:236`, `let _ = span`), so provenance diagnostics have no line or column.
  - `ComponentMapping { .. }` is built as a 10-field literal at 9 sites: `component.rs:116,170,206,243,298,344,383`, `visit.rs:299` and `interface.rs:319`.
  ```rust
  enum Detection { Component(ComponentMapping), Skip { reason: SkipReason, span: Span }, NotCandidate }
  fn classify(&mut self, d: &VariableDeclarator, name: &str) -> Detection  // one peel_expr(), one match on call shape
  impl ComponentMapping { fn new(name, props: PropsRef, span: Span, ..) -> Self }  // 9 literals -> 1
  ```
  - Use an enum or plain functions, not trait objects. They are not needed here, and the code stays per-file and monomorphic.
  - Set `preserve_parens: false` (one line, fixes D7).
  - Add one `Diagnostic::at(file, span.line_col(source))` helper so `SkippedCandidate` and the new `InferredComponent` carry a position.
  
  **3. Remove `ResolveState` forking and the `too_many_arguments` allows.** Effort M. Risk medium: touches cycle semantics, so it needs the existing diamond and cycle tests.
  - The struct literal copying `visited`, `named_in_progress` and `in_scope_type_params` appears 3 times: `chain.rs:229`, `alias.rs:50`, `alias.rs:290`. It clones three hash sets per extends branch, so cost grows with chain depth.
  - Make `visited` an "on this path" set (insert on entry, remove on exit), as `named_in_progress` already is (`named.rs:38,60`). The diamond false-positive then cannot occur and no fork is needed. Forks may still be needed to isolate diagnostics.
  - 10 `#[allow(clippy::too_many_arguments)]` sit on functions threading `(consuming_file, mapping, ctx, state, depth)`: `chain.rs:19,198`, `extends.rs:15`, `alias.rs:15,275`, `named.rs:21,59`, `collected.rs:15`, `func.rs:10`, `output.rs:158`.
  ```rust
  struct Cx<'a> { ctx: &'a ResolutionContext, mapping: &'a ComponentMapping, file: &'a Utf8Path, depth: u8 }
  fn resolve_props_chain(cx: Cx, state: &mut ResolveState, name: &str, args: &[CollectedType]) -> ResolvedChain
  ```
  
  **4. Typed declaration keys instead of `"path:Name"` strings.** Effort M to L. Risk medium.
  - Six `FxHashMap<String,_>` in `GlobalSourceData` use string keys. `NamedTypeIndex::build` (`named_type_index.rs:~110-125`) rebuilds them as nested maps by `rsplit_once(':')` and deep-clones every interface and alias (`iface.clone()`).
  - `remove_file` (`global.rs:113-120`) does 6 full `retain` scans with `starts_with(prefix)`.
  - `file_path: Utf8PathBuf` is cloned into every mapping, interface, alias and `AtFile` (`substitute.rs:67`).
  - Recommended: `FxHashMap<Arc<Utf8Path>, FileDecls>` as the only store (this removes `NamedTypeIndex` and its duplicate copy), keyed by `(file, CompactString)` with an `Arc<Utf8Path>` newtype. A `FileId(u32)` is the later step.
  - Step 1, S effort: change the two `.clone()` sites of `CollectedTypeAlias` to references. `precedence.rs:53` and `named.rs:180` clone an alias per lookup, even though `SourceOrKnownMatch<'g>` already has the lifetime for `&'g CollectedTypeAlias`.
  
  **5. One options spec for CLI and NAPI; wire or delete the dead fields (D3).** Effort S to M.
  - `binding/lib.rs:115-165` and `cli/config.rs:33-77` are near-identical 40-line mappers into `PipelineOptions`, including the same two format strings. They already drifted: `exclude_prefixes` exists only in the CLI; `extra_paths`, `known_type_overrides` and `resolve_complex_types` only in NAPI.
  - Put a `serde` `OptionsSpec` with `deny_unknown_fields` and `TryFrom<OptionsSpec>` in core. Use a typed `OptionsError` (thiserror) instead of `Err(String)`.
  - The CLI already uses `deny_unknown_fields`; the NAPI object cannot.
  - The napi layer should return `Status::InvalidArg` instead of `from_reason` (14 sites).
  
  **6. Watch-mode state.** Effort M. Risk medium.
  - `update_file` does `self.global.rcu(|old| { let mut g = (**old).clone(); ... })` (`watch.rs:~199`). That deep-clones the whole `GlobalSourceData` on every save, and again on every rcu retry.
  - It conflicts with the incremental `NamedTypeIndex` work done to avoid exactly this cost.
  - `global`, `named_types` and `component_cache` are patched under different locks, so two concurrent edits to the same file can leave them disagreeing (trace only).
  - Recommended: one `Mutex<WatchState>` held for the whole mutation phase, with per-file `Arc<FileData>` so patching is O(file), plus `Arc::make_mut` as already done for `named_types`.
  - The `contain_panic` + stub `ComponentEntry` block is duplicated at `pipeline/mod.rs:~420-440` and `watch.rs:~246-265`. Extract one `resolve_guarded(mapping, &ctx)` and test both paths through it.

  ## C. Performance: where to look first (evidence, not guesses)
  
  - **Scaling:** Mantine core on 18 cores takes 44 ms with all threads and 68 ms with `RAYON_NUM_THREADS=1`, so only about 1.5x scaling. A large share of wall time is serial: discovery, merge, `ResolutionContext` build, output.
  - **Discovery:** `discover.rs:25` uses sequential `WalkBuilder::build()`.
  - **Duplicate TS lib resolution:** `typescript/package.json` is resolved twice per run, in Phase 3.6 and again in `ResolutionContext::new` via `compute_ambient_global_files`. The second call took about 1 ms in the log.
  - **RDT output (not measured):** `cli/extract.rs:100-131` builds a `serde_json::Value` tree with `json!` and then pretty-prints it, instead of serializing typed structs from core.
  - **Worst clone/alloc sites** (counts: 123 `.clone()`, 186 `to_string`/`to_owned`):
    1. `named.rs:30-36`: a `format!` plus `to_raw_string` + `join` for the visit key on every named-type resolution.
    2. The `ResolveState` forks (`chain.rs:231`, `alias.rs:52,292`).
    3. The alias clone per lookup (`precedence.rs:53`, `named.rs:180`).
    4. `NamedTypeIndex::build` deep-clone, plus `DtsCache::get` clone-on-read and `insert(.., data.clone())` of the parsed `SourceData` (`pipeline/mod.rs:~318,545`).
    5. `substitute_type` (`substitute.rs`, 24 clones) rebuilds the whole tree even when no parameter occurs.
  - **Unmeasured:** I did not run criterion or profile allocations, so the size of these costs is unquantified. Do a profile before changing 2 to 5.
  - **Allocator:** `mimalloc` for the CLI is a cheap thing to measure, as OXC-based tools often use it. NAPI cannot.
  - **Locking/globals:** no lock contention found. `DashMap` is used for the DTS cache, `watch.rs` caches and `SESSIONS` (`binding/lib.rs:14`). Cache eviction (`cache.rs:~160`) takes 100 arbitrary keys from DashMap iteration.
