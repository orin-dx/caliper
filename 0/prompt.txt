  ## 2. Import and type resolution
  
  **`resolve_to_canonical`** (resolver/import.rs:38-66)
  - It first calls `find_import(file, name)`. On a hit it resolves the specifier, then runs `follow_reexports(resolved_file, exported_name)`.
  - Otherwise it splits `A.B` at the first `.`. If `A` is a namespace import (`exported_name == "*"`, :60), it follows `B` from the namespace's module (:58-65).
  - It returns `None` for a local name. Callers then fall back to `(consuming_file, name)` (precedence.rs:47-48).
  
  **`resolve_import_specifier`** (import.rs:203-239) and **`ModuleResolution`** (:192-200)
  - The memo is keyed `(dir, specifier)` (:211-219). `resolve_module` (:241-266) handles bare specifiers with `react::resolve_package_types_file` (react.rs:129-142).
    - That function tries `resolve_dts` and accepts `.d.ts`, `.d.mts` or `.d.cts`, then retries `@types/<mangled>`. A hit becomes `ModuleResolution::PackageTypes(path)`.
    - Relative paths go through `oxc_resolver.resolve` and become `File(path)`.
  - `PackageTypes(path) => Some(path)` (:221) records **no** dependency. `File` calls `deps::record(&path)` (:222-225). `Unresolved` pushes a Warning `UnresolvableImport` "Cannot resolve '{spec}' from '{file}'" (:226-237).
  
  **`follow_reexports`** (:75-123)
  - It records `file`, then stops if `named_types.is_declared_at(file, name)` is true (types only, meaning interface or alias). Otherwise it uses `resolve_reexport_chain` (import_map.rs:94-122):
    - `Named` hops.
    - `Wildcards` tries each `export *` target and keeps the first one where the name is declared.
  - `ReExportNamespace` (`export * as Ns`) is ignored (import_map.rs:112).
  - Depth is capped by `MAX_REEXPORT_DEPTH = 8`, and a visited set prevents loops.
  
  **What happens when the resolved file is a `node_modules` `.d.ts` that was never parsed**
  1. `resolve_import_specifier` returns `Some(pkg.d.ts)`, with no diagnostic and no dependency recorded.
  2. `follow_reexports` finds no declaration and no re-exports, so it returns `(pkg.d.ts, name)`.
  3. `lookup_type_alias` and `lookup_interface` miss (precedence.rs:50-60), then `resolve_known` runs (:62).
  4. In `named.rs` (type level), the remaining checks run in order:
     - React builtin fallback (:137-140).
     - The silent `Named` list (:146-174).
     - In-scope type parameters (:177).
     - The ambient lib lookup by bare name (:188-196). It does **not** check the binding, so an imported name that collides with a lib.dom global is silently taken as that global.
     - Finally a Warning `UnresolvableImport`: "Cannot resolve type 'X' in 'file' (resolved to 'X' in '<pkg>.d.ts') — it will appear as an unexpanded named reference" (:199-214).
  5. In `chain.rs` (props level), the checks are:
     - Step 2.5 React builtin (:150-156).
     - The `html_element_for` terminal (:160-162).
     - Step 6 Warning "Cannot resolve type …" plus the type name in `composes` (:168-181).
  6. The " (resolved to …)" suffix comes from `unresolved_location_note` (resolver/mod.rs:75-87).

  ## 4. Keys, identity and globals
  
  - `GlobalSourceData` maps are keyed `"{abs_path}:{name}"` (types/global.rs:77-98). Merging the same key merges declarations (props and extends concatenated, :113-125). Nothing merges across files, so augmentations do not merge.
  - `NamedTypeIndex` (named_type_index.rs:27-34) is `PathKey → name → value`. Keys are split on the last `:` (:118-140). `react_namespaced` gives the `React.X` fallback.
  - `ImportResolutionMap` is keyed by `PathKey` (import_map.rs:41-50).
  - Ambient globals:
    - `ambient_global_files` holds only lib.es5 and lib.dom (resolver/mod.rs:305-313, 339).
    - It is used by `lookup_ambient` (bare name, after every other step; named_type_index.rs:221-231; named.rs:188) and `lookup_interface_including_ambient` (primitives.rs:141).
    - `react.d.ts` is not ambient. `JSX.Element` only works as a hard-coded builtin name (react_types.rs:93).
    - `declare global { namespace JSX }` would be keyed `file:JSX.X` and never looked up globally.
  
  **Implications**
  - Dependency types need:
    - Per-module `export =` and namespace-merge support, generalizing the React-only qualified fallback.
    - Optionally, "global" scopes from `declare global` in dependency files.
    - Real augmentation merging (keyed by the target module) for MUI-style overrides. Today `OverridableStringUnion` is a shortcut (known.rs:99-112).
  - Bare-name enum indexes: `enum_bare_index` (resolver/mod.rs:269-286) is "sorted, first wins". `/proj/node_modules/…` sorts before `/proj/src/…`, so a **dependency enum would shadow a project enum**.
  - `collect_public_enums` (pipeline/mod.rs:289-330) iterates every exported enum, so a dependency's `export declare enum` would **leak into output `enums`** and could produce `DuplicateEnumName` warnings.
  - Both need a project/dependency origin filter.

  ## 7. Cache
  
  - `DtsCache` (cache.rs:117-124) is keyed by `(path, FxHash(content))` (:76-86). Content is hashed, not mtime or size.
  - It is a `DashMap` with `MAX_CACHE_ENTRIES = 5000` (:111). Eviction drops an arbitrary 100 entries when full (:227-232).
  - The whole store is loaded into memory and rewritten in full (header plus `Vec`) on any dirty save (:171-195, 264-289), defaulting to `node_modules/.cache/caliper-docgen` (:143-144).
  - `counts()` (:203-205) returns `(lookups, hits)`, which become `dts_files_parsed` and `dts_cache_hits` (revision.rs:241). Project `.d.ts` files and react/lib files are counted together.
  - Header: `CACHE_SCHEMA_VERSION = 14` (:31), plus crate version and a `build.rs` source fingerprint (:38-54). ADR 0003 makes `SourceData` positional, so a schema bump is needed for any non-append field change. ADR 0008 discards the cache on any build change.
  - **`MAX_CACHE_FILE_BYTES` does not exist on this branch.** grep finds nothing in crates/ or docs/.
  
  **Implications**
  - Dependency graphs (MUI or Radix can mean thousands of `.d.ts` files) will thrash the 5000-entry cap with random eviction. Whole-file rewrites and full in-memory load also scale with dependency count.
  - Consider a separate cache keyed by package path and version, or sharding.
  - Content hashing still requires reading every dependency file each run.
  - Any new `SourceData` field (value-declaration index, module augmentation target) needs `CACHE_SCHEMA_VERSION` bumped.

  ## 9. ADRs and docs
  
  - **ADR 0001:** structural OXC resolution. Gaps "degrade to a Diagnostic plus Opaque, never a silent wrong answer". Nothing about `node_modules`; its consequences cite parallel per-file parsing with no shared `Program`.
  - **ADR 0004** (superseded by 0006): defer the checker. The semantic process stays outside `crates/core`, and core has no I/O or async responsibility for it.
  - **ADR 0006:** opt-in tsc `--api` second resolver, merged per component. "Structural stays the default and the fallback." It notes tsc sees a dependency edit only when told.
  - **ADR 0007:** the backend may discover components. It is always compiled in, enabled at runtime, structural is the default, and it triggers only for components "the structural pass marked incomplete".
  - **docs/type-checker-integration.md:**
    - Boundaries: core owns the merge and has no I/O, async or protocol types for the backend.
    - Its "What gets dropped" table lists "Ambient `.d.ts` components such as `PureComponent`" as handled.
    - Its gap list (generics through aliases, conditional and mapped types) does not cite missing dependency `.d.ts`.
  - None of these ADRs addresses loading dependency `.d.ts`.
  
  **Verdict:** loading dependency `.d.ts` structurally contradicts no ADR.
  - It is the same mechanism already used for `@types/react` and the lib files.
  - Core already does file I/O in the pipeline. ADR 0004's no-I/O rule applies to the semantic client.

  **Implications**
  - With dependency interfaces expanded, inherited props (for example Radix `SelectProps`) get `parent.file_name` under `node_modules`. That matches RDT semantics, so Storybook's default RDT `propFilter` would hide them, as it does with RDT.
  - Canonical and storybook output would then contain a large number of extra props, with no filter on our side.
