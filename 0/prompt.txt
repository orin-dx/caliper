## Deviations
- **Ported onto the landed stack, not copied from the experiment.** It uses #97's module resolvers (no second resolver), #101's `ComponentProps&lt;typeof X&gt;` handling and #105's interface memo (no `CALIPER_MEMO`). The env-var switch became a flag, and the stats env hook is gone.
- **New: `export { DialogContent as Content }`.** The extractor dropped the local name behind this Radix-style alias, so those parts were reported as "not exported". Fixing it adds a field to a public extractor type, a breaking Rust API change noted in the changeset, and bumps the parse-cache schema to 16.
- **Collapse is never applied** to a component's own props type, to the base of a `Pick`, or to a `keyof` operand. Collapsing those would drop props the code selects or counts by name.
- **One regression found and fixed before pushing #109.** My first version skipped the shared-results cache under `Pick`/`keyof`, which made chakra 3× slower and 900 MB larger with identical output. The cache now keys on that case instead; `none` mode times the same as #107.

## Collapse (#109)
- **Default mode:** shadcn goes from 12,937 to 7,447 props (88 collapsed layers) and antd from 4,489 to 3,821.
- **Chakra is unchanged by default:** its 399k props come from its own `styled-system` sources, which only `all` collapses. That matches ADR 0012 for a design system's own repository. With `all`, chakra drops to 5,541 props, 13.6 MB and 381 ms / 842 MB, against 438 ms / 1,271 MB for #107.
- **Cost of the default on chakra:** about 8% time and 110 MB, because part of the shared-results cache splits even though nothing collapses there.
- **Identity:** with collapse set to `none`, flag-on output is identical to #107's; flag off is identical to #107; the default mode is deterministic at 1/4/18 threads.

## Before turning the flag on by default
1. **Chakra-style repositories:** decide whether the default collapse should also cover large project sources. With `dependencies`, chakra stays 12× slower than flag off and its output 27 MB.
2. **Alias names:** print a type alias by name where RDT does. This is the main reason changed types match RDT less often.
3. **Handler merging:** fix the recharts-style overwrite of DOM event handlers.
4. **Watch:** it doesn't watch `package.json` or `node_modules`, so a reinstall needs `rebuild()`. The loaded dependency types also only grow within a session.
5. **Collapse in watch mode:** its timings weren't measured separately. The notable-props list is the generic HTML one, so a style-props source keeps only names that happen to match it.
