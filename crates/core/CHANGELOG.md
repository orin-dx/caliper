# caliper-docgen-core

## 0.11.0

_2026-11-14 · [compare](https://github.com/orin-dx/caliper/compare/caliper-docgen-core@0.10.0...caliper-docgen-core@0.11.0)_

### Minor Changes

- An anonymous default export is now a component of its own, and a named export of the file's name beside it is another. In `E.tsx`, `export const E = forwardRef(…)` beside `export default forwardRef(…)` used to give two components named `E`, each listing both `E` and `default` as its exports, so a lookup of `E` or of `default` found two and the Storybook addon could not choose. Now the named one is `E` with exports `[E]` and the default one is `E (default)` with exports `[default]`, in whatever order the file writes them. A default export keeps the bare file name when no other component of the file has it, so existing output does not change. A default export a call wraps (`export default React.forwardRef(InternalTable) as T`, `export default memo(forwardRef(Card))`) now lists `default` as an export of the component the call wraps, which it did not before. The Storybook addon no longer reads a story's module source to find that component, and finds it from the exports like any other. The output's shape is unchanged, and the parse cache is rebuilt once.

  For library users: `ComponentMapping` has a new field, `bound`, false for a component that is no binding of its name (an anonymous default export or an inline sub-component), and `ComponentMapping::without_binding` sets it.
- `bigint` is now a type of its own in the canonical JSON: a prop typed `bigint`, or `React.Key` (`string | number | bigint`), has `{ "kind": "bigint" }` where it had a type named `bigint`, whether Caliper read the type itself or the TypeScript checker (`--experimental-semantic-types`) did. The output's `schemaVersion` is 6, so the Vite plugin and the Storybook addon need the same release as the binary, and the parse cache is rebuilt once. The RDT output and the Storybook control are unchanged: the type is still `bigint`, which Storybook has no control for. For library users: `PropType` gains the variant `BigInt`, so an exhaustive `match` on it needs a new arm.
- The core crate no longer reads its canonical JSON back into Rust types, since nothing in Caliper did (the Vite plugin and the Storybook addon read the JSON in TypeScript). `ExtractionOutput` and `PropType` lose their `Deserialize` impls, and the types they hold lose theirs too: `ComponentEntry`, `ParsedProp`, `InheritedLayer`, `DefaultValue`, `PropParent`, `OpaqueReason`, `FunctionParam`, `ObjectField` and `ExtractionStats`. All of them still implement `Serialize`, and the JSON written is byte-for-byte what it was. A library user who parsed that JSON with these types needs their own types for it.
- With the TypeScript checker on (`semanticTypes: 'on-demand'`, `--experimental-semantic-types`), a component the checker answers for no longer keeps the warnings Caliper's own pass reported about what that answer replaces, such as "Cannot find the component 'Button'" or a prop type it could not resolve. In Storybook, with the default `fallback: 'degraded'`, such a component (Chakra's `Button` among them) now shows the checker's props instead of being handed to React's docgen. Warnings about what the checker could not read either, and the checker's own (it stopped, it is unavailable), stay and still hand the component on. A warning shared by several components now lists only the ones the checker did not answer. For library users: `DiagnosticCode::superseded_by_checker` says, for each code, whether a checker answer supersedes it (the new `Superseded` enum).
- `extract` keeps the checker's answer in its cache directory, and a rerun over unchanged files reuses it: on an app wrapping the 938 components of Chakra UI and MUI a rerun takes 0.25 s instead of 1.4 s. Before reusing it, the run asks again every question the checker asked of the disk (each file it read or looked for, each directory it listed, the tsconfig and what it extends); any different answer, a new file where it found none included, discards it whole, as does another Caliper build. `--no-cache` neither reads nor writes it, and `check`, `inspect`, a `--tsc-path` checker and the Storybook session never use it.

  A whole-project `extract` with the checker is also faster and smaller when it does ask: each property's type is asked for once per run instead of once per component, and fewer files are asked about at once. On the same app it takes about 1.4 s and 990 MiB instead of 1.7 s and 1,080 MiB; on the Chakra components alone about 1.1 s and 720 MiB instead of 1.35 s and 870 MiB. The output is the same.
- With the TypeScript checker on (`--experimental-semantic-types`, or `semanticTypes: 'on-demand'`), a component now gets the props of its own export. Before, a component the checker could not find by its name took the props of the module's default export: with `Menu.Item = Item; export default Menu`, `Item` was given `Menu`'s props and reported as resolved by the checker, and with `export { CardImpl as Card }` beside a default export, `CardImpl` was given the default export's props. Now the checker asks for the export the component really has (a renamed export, `default`, or `Menu.Item` through its parent), and a component it cannot find that way keeps the props Caliper read itself, with the reason in a `SEMANTIC_BACKEND` diagnostic. The output's shape is unchanged, and the parse cache is rebuilt once.

  For library users: `ComponentMapping` and `ComponentEntry` record how the module exports each component (`exports`, a list of `ComponentExport`), and `ComponentMapping::exported()` replaces the `exported` field. `SemanticTarget` carries the component's output `key` and its `exports` in place of `exported`, and `SemanticComponent` and `SemanticFallback` name the component by that `key` in place of `file_path` and `display_name`; the merge finds the entry by key.
- The TypeScript checker built into Caliper is now the only one it runs. The option that ran a checker binary as a separate process instead is gone, and with it the version check of that binary. Output with the built-in checker is unchanged.

  Breaking: `--tsc-path`, the config's `tscPath`, and the `tscPath` option of the native binding and the Storybook addon are removed. The CLI and the config refuse them as unknown, and the addon refuses `tscPath` by name, since left unread it would quietly run a different checker than the one it named. For library users, `caliper-docgen-semantic` loses `SemanticRequest::tsc_path`, `expected_versions` and `extra_env`, `OnDemandConfig::tsc_path`, `expected_versions` and `extra_env`, `OnDemand::process_id`, `OnDemand::recycles` with `Recycles` (the built-in checker is never replaced), and `SUPPORTED_VERSIONS`, and no longer depends on `caliper-docgen-tsc-client`, which is not released any more; `caliper-docgen-core` loses `PipelineOptions::semantic_tsc_path`.

  Action: drop `--tsc-path` and `tscPath`. The built-in checker answers without them; nothing needs to be installed.
- The built-in TypeScript checker now answers by default (ADR 0026). `extract`, `check` and `inspect` merge its answer over the structural one, prop by prop, and wait for it. A native session and the Storybook addon ask it for each component a request names, and still show the structural props first when it is slower than `semanticWaitMs` (150 ms). `--no-checker`, or `checker: false` in `docgen.config.ts`, the native options or the addon's options, runs the structural resolver alone, as before. `watch`, `extractAll` and the Vite plugin stay structural.

  The checker costs time and memory. `extract` of an app with 938 Chakra UI and MUI components takes about 6 s and 970 MiB, against 0.1 s and 200 MiB with `--no-checker`. A session that answered every one of them peaks at about 1 GB, against 380 MiB without the checker: each answer the session keeps now shares its props with the others, where before each kept its own copy, about 6.7 MiB per Chakra component.

  Breaking: `--experimental-semantic-types`, the config's `experimentalSemanticTypes` and the `semanticTypes` option of the native binding and the Storybook addon are removed. The CLI and the config reject the old names as unknown, and the addon rejects `semanticTypes` by name. `PipelineOptions::experimental_semantic_types` is now `PipelineOptions::checker`, and it is `true` by default.

  Action: drop `--experimental-semantic-types`, `experimentalSemanticTypes: true` and `semanticTypes: 'on-demand'`, since the checker now runs without them. Replace `semanticTypes: 'off'`, or a run that relied on the old structural default, with `checker: false` or `--no-checker`.
- With `semanticTypes: 'on-demand'`, a story whose component the TypeScript checker is already answering (for the warm-up, a fill, or another story) now waits for that answer instead of asking the checker again behind it, and the checker answers the stories you open before warm-up and fill work. `sessionWarmUp` no longer waits for the checker: it queues each component behind the stories, and the answers are kept for the stories that follow. Background work still runs: after 4 story answers in a row it gets the next turn. For library users: `WatchSession::components_in_background` asks at background priority without waiting, `SemanticProvider::request_at` takes a `SharedPriority` and a `Delivery` (with a default that calls `request`), and `OnDemand` answers by priority.
- With `semanticTypes: 'on-demand'`, the warm TypeScript checker keeps its snapshot between requests and brings it up to date with the files the session says changed (`updateSnapshot`), instead of reading the whole program again for every request. Answers are the same bytes as before. An edit nobody announced (a file the checker read changed, and neither `update_file` nor `ensure_fresh` saw it) is found before the checker answers from the old text: that answer is read again from the disk and carries a `SEMANTIC_BACKEND` warning naming the file. A checker warning that comes with an answer is now shown on every answer it applies to; only "unavailable" is still said once per session.

  For library users: `SemanticProvider::changed(SourceChange)` is how a `WatchSession` tells its checker what changed (a default that does nothing suits a provider that reads every file afresh), and `OnDemand::snapshots()` counts the snapshots answers came from, `created` from the disk or `updated` from the one before. The checker is still off by default.
- With `--experimental-semantic-types` or `semanticTypes: 'on-demand'`, a prop the TypeScript checker answers for takes its `parent`, `declarations` and JSDoc tags from the checker, and the component its `composes`, instead of from Caliper's own pass. `parent` keeps its meaning: the interface that declares the prop, with the file as it is on disk, and none for a prop of a type literal; a prop picked or omitted from an interface (`Pick`, `Omit`) names that interface. `composes` lists the React types the props type is made of (`RefAttributes`, `HTMLAttributes`, also of a generic interface instantiated as `Props<string>`), no longer the types Caliper could not follow where the checker did. A union's members the checker sorted are put back in the written order in more cases (a union of string values, a type named through a namespace, an `undefined` Caliper dropped). The checker asks for descriptions in one round trip per component, and once per declaration, so a whole run is faster (938 Chakra and MUI wrappers: about 15 s to 9 s). The checker is still off by default. For library users: `SemanticProp` has `tags`, `parent` and `declarations`, `SemanticComponent` has `composes`, `None` when the checker could not tell and the structural `composes` stays, and `merge_semantic_props` takes the component's `composes` as an `Option<&[String]>`.
- With `--experimental-semantic-types` or `semanticTypes: 'on-demand'`, a prop whose type the TypeScript checker could not read (a name it did not resolve, a conditional type it left open) no longer has its type replaced by the checker's placeholder when Caliper read that type in full itself: the prop keeps Caliper's type, its `degradedBy` names what the checker could not read, and one info diagnostic counts those props. A type the checker only cut at a size or depth limit is still the checker's. The checker is still off by default. For library users: `merge_semantic_props` returns `MergedProps` (`kept`, and `unread` for these props) instead of a count, and `apply_semantic_props` returns how many props kept their type this way.
- With `semanticTypes: 'on-demand'`, a story whose component Caliper's own pass lists no props for (such as `ComponentProps<typeof Button>` of a library it cannot read, which is most of Chakra) now waits up to 2 seconds for the TypeScript checker instead of showing no props after 150 ms: Chakra's `Button` now shows the checker's 1,138 props on its first request. Components Caliper lists props for still answer within `semanticWaitMs`, exactly as before. The new option `semanticWaitEmptyMs` (default `2000`) sets the longer wait; a checker slower than it is still kept for the next request. For library users: `WatchSession::with_semantic_wait_empty` sets the same wait.
- Breaking for Windows users: Windows is no longer a supported platform; use WSL. Caliper no longer builds or publishes `x86_64-pc-windows-msvc` binaries, and the `caliper-docgen-win32-x64-msvc` and `caliper-docgen-napi-win32-x64-msvc` npm packages are removed from the optional dependencies of `caliper-docgen` and `caliper-docgen-napi`, so installing on Windows no longer fetches a binary.
- The canonical JSON now says how each component's module exports it: `exports`, a list of `{ name, members }` per component (`default` for the default export, `Card` for `export { _Card as Card }`, and for a sub-component attached to an export the export it hangs from with the property that reaches it, so `Menu.Item = Item` beside `export default Menu` is `default` with `Item`). The session index the Storybook addon reads lists them too. Readers can find a component by file and export instead of by display name, which two components of one file can share. The output's `schemaVersion` is 7, so the Vite plugin and the Storybook addon need the same release as the binary, and `caliper-docgen schema` and the TypeScript declarations list the new field. The RDT and TOON output are unchanged, and the parse cache is not rebuilt. For library users: a `ComponentEntry` read back from the JSON has its `exports`, which it did not before.
- A component its module exports under exactly one other name is now reported under that name: `export { _Card as Card }` is `Card`, where it was `_Card` (and `export { Wrapped as DialogTrigger }` is `DialogTrigger`, where it was `Wrapped`). A component with a `displayName`, one exported under its own name or under several names, one reached through a parent, and one whose export name another component of the file already has keep the name they had. The canonical JSON's `exports` is unchanged and still identifies the component (ADR 0027), and the module's own binding is kept in the new `ComponentMapping::local_name`, so `typeof _Card` inside the file and through the export from another module still resolves.

  Breaking: the `displayName` (and output key) of such a component changes, so a reader that looks it up by the old internal name (`components["_Card"]`) no longer finds it. `ComponentMapping` gains a public field, `local_name`. The canonical schema version is unchanged (7).

  Action: look a component up by its export (`exports`), or by the new name. The declaration cache is rebuilt once (schema 38).
- `OpaqueReason` now serializes as the canonical JSON writes it, `{ "type": "runtimeDependent", "functionName": "cva" }`, where its own `Serialize` gave serde's default `{ "runtimeDependent": { "function_name": "cva" } }`. The extraction output is unchanged, since it already wrote the first form. A library user who serialized an `OpaqueReason` on its own gets the new shape.
- The unused plugin system is removed from `caliper-docgen-core`: `DocgenPlugin`, `PluginRegistry`, the `plugin` module and the `plugins` field of `PipelineOptions` no longer exist. Nothing in the CLI, the Vite plugin or the Storybook addon could register a plugin, so extraction output is unchanged. Code that implemented `DocgenPlugin` or set `PipelineOptions.plugins` needs to drop it.
- With `--experimental-semantic-types` or `semanticTypes: 'on-demand'`, a prop the TypeScript checker answers for takes its default and the order of its union's members from the source itself: the default the component's code gives it (a destructured parameter's initializer, `defaultProps`), else its `@default` tag, and the members in the order its declaration writes them. Props only the checker returns now have both too (938 Chakra and MUI wrappers: 834 more defaults, 1,452 unions in written order), and a few unions Caliper's own pass ordered wrong are fixed (`slot?: string | null`). Members that come through an imported type keep Caliper's own order, as before. For library users: `merge_semantic_with` takes a `ResolverFacts`, `MergedProps` has `diagnostics` and is no longer `Copy`, `apply_semantic_props` is gone (`merge_semantic` does what it did), and the merge functions read the source files the answer names.

### Patch Changes

- A whole-project `extract` with the checker (the default) is about three to four times as fast, with the same output. On an app wrapping the 938 components of Chakra UI and MUI it takes 1.8 s instead of 6.2 s, and 1.4 s instead of 5.7 s for the 787 Chakra components alone; `react-docgen-typescript` takes 7.3 s and 4.1 s on the same files. The checker's answer for a prop that many components share (Chakra's style props) is now converted and merged once instead of once per component, the answers are read on several threads, and the built-in checker answers two programs over the same files at once. Peak memory is about 10% higher (1.1 GiB instead of 0.98 on that app; 1.5 GiB on three copies of it). The Storybook session keeps asking one program.
- The experimental TypeScript checker is now built in: `--experimental-semantic-types` and `semanticTypes: 'on-demand'` use the `tsrs` checker linked into Caliper, so there is nothing to install, and a project's own `typescript` or `tsrs` is no longer looked for. It is still off by default. The CLI binary and the native binding are each about 22 MB larger, and their npm packages carry tsrs's `NOTICE`.
- Merging the checker's answer is faster on a design system: a prop the answer repeats under every component that inherits it, and a file it names again, no longer cost a path allocation and a hash each; a component's props are built into its map in one pass; and the dependency loader keeps its export table without re-hashing it. The output is byte-identical.
- `exclude` patterns are now globs, as the Storybook README always said, matched against each file's path inside its source directory. `*.fixture.tsx`, `legacy/` and `**/internal/**` work; before, a pattern excluded any file whose path merely contained that text, so `Button` also dropped `ButtonGroup.tsx`. Now `Button` excludes only a file or folder named exactly `Button`. A pattern that is not a valid glob is reported and excludes nothing, and an empty pattern excludes nothing instead of every file. Patterns follow gitignore: `['*', '!*/', '!*.tsx']` keeps every `.tsx` file in every folder, including the folders themselves in watch mode (a file created later is noticed), while a `!` pattern cannot bring back anything inside a folder an earlier pattern excluded. The error for a bad `docgen.config.ts` now lists exactly the options the config accepts.
- A `.gitignore` is now applied to a project inside a folder merely named like `node_modules`, such as `node_modules-backup`, instead of being switched off. No action needed.
- A plain `/* note */` comment above a prop is no longer shown as its description, and a tag such as `@deprecated` or `@example` now keeps the lines after its first. No action needed.
- Components in `.mts` and `.cts` files are now found and watched like those in `.ts` and `.tsx` files, where they were skipped before. No action needed.
- `extract --format rdt` on a large project is more than twice as fast and needs about a quarter of the memory, with byte-identical output: 1.8 s and 1.1 GiB instead of 4.3 s and 3.7 GiB on the largest project measured, and 1.4 s and 0.9 GiB instead of 3.9 s and 3.6 GiB on the 787 Chakra components. The document is written as it is rendered instead of being built whole, and each distinct prop (a few thousand, shared by half a million occurrences) is rendered once.
- A prop typed `React.ReactElement` or `JSX.Element` is no longer reported as `ReactNode`, which also accepts strings, numbers and `null`: the checker's answer keeps it as the named type `ReactElement<…>` with its arguments, or `JSX.Element`, so Storybook shows the type the prop takes. `JSX.Element` is named through its namespace, so it is not confused with the DOM's `Element`, and in a union such as `Element | React.JSX.Element | null` each member keeps the place it was written in. Only the checker path changes; `--no-checker` still reads both as `ReactNode`. The JSON schema is unchanged.
- A component whose name starts with an underscore is now found: `export default function _3D(props: { size?: "L" | "M" | "S" })`, which is how a file named `3D.tsx` has to spell its function, was skipped with no note before, and so were `_Card` and `_Box`. A name needs a capital letter after the underscore and any digits (`_helper` and `_3d` are still not components), and the function still has to render something. The parse cache is rebuilt once.

## 0.10.0

- `export const Button = InternalButton` and `memo(InternalButton)` are components even when `InternalButton` is declared further down the file; the alias used to be dropped, and reported as a skipped candidate, whenever it came first.
- Editing a file a component only imports, such as the one that declares its props interface, now makes the TypeScript checker answer again for that component. A session with `semanticTypes: 'on-demand'` used to keep showing the checker's types from before the edit until the component's own file changed.
- A type written as `{ (a: string): number }` is a function type, where it used to come out as an empty object. A type with several call signatures, or a call signature next to properties (react-hook-form's `watch` and `getValues`), is marked as one the tool could not express, with `degradedBy: ["unsupportedExpression"]`, instead of an empty object with no warning. A prop whose index signature key is a template literal such as `` `data-${string}` `` now carries `degradedBy` too.
- A TypeScript checker that stops without answering a request is reported as a warning on the component, as a slow one already was, and a panic while loading a type a dependency declaration refers to is reported as an `InternalPanic` diagnostic instead of ending the load. Before, the first left the structural props with no explanation and the second was not contained.
- With the experimental TypeScript checker on, a prop whose type is a name that does not resolve (an import that cannot be found, a name declared nowhere) is no longer reported as `any`. It is `opaque` and carries `degradedBy: ["unresolvableImport"]`, so a reader can tell it from a prop written as `any`.
- A reply from the TypeScript checker that is not valid JSON is now reported as a warning on the component right away. Before, the reply was dropped and the request waited out its full timeout, then reported a timeout.
- The default CLI and NAPI output now keeps a dependency's own API with its types, such as antd's `onClose`. DOM and ARIA attribute families and style systems collapse to a list of names once they pass 30 props, and any other dependency source once it passes 200 (Chakra v3's 705-prop style system). The Storybook addon is unaffected because it already lists every inherited prop.
- `Root.Item = memo(...)` and `Root.Item = forwardRef(...)` now leave a skip note saying the sub-component is not read, instead of vanishing from the output without a word. Other assigned calls, such as `Root.Context = createContext(...)`, stay silent because they are not components.
- Props typed from a constant now carry the value TypeScript gives them: `typeof SHOW_PARENT` over `const SHOW_PARENT = 'SHOW_PARENT'` is `"SHOW_PARENT"`, `keyof typeof Icons` over an object literal is the union of its keys, a union of `true` and `false` is `boolean`, and a component exported as `Masonry as (<T>(props: PropsWithChildren<P<T>>) => Element)` has the props of that function type, `children` included.
- A constant such as `MENU_OPTIONS` or `ORIGIN` is no longer reported as a skipped component candidate: on shadcn/ui and Ant Design that removes 211 of the 398 skip notes (163 of 252 and 48 of 146), with the extracted components unchanged.
- A dependency declaration file that exists but cannot be read (bad permissions, invalid UTF-8) is now reported as an `IoError` warning naming the file, instead of being skipped without a word, which left the types it declares missing with no explanation. Concurrent runs also no longer share one temporary file when saving the dependency type index.
- A default written in a destructured parameter is now recorded under the prop it belongs to, even when the prop is renamed as in `{ 'aria-label': label = 'x' }`, and defaults like `-1` or `!0` are no longer marked as computed. No action needed.
- Remove the `DiagnosticCode::ComputedDefault` variant and the `DefaultSource::JsDoc` variant from the Rust API. Nothing constructed either, so no output ever carried them; only Rust code naming them directly breaks.
- A prop typed with a TypeScript enum whose members are all literal now shows the union of the enum's values, such as `'primary' | 'secondary'`, instead of an unresolved name with a warning that made `check --strict` fail. Declarations that merge into one enum contribute all their values. An enum with a value that is not a literal, a boolean or an expression, still shows its name with the warning, as does a `declare` enum whose members have no initializer, since its values are unknown. A conditional type that tests a value against an enum, such as `"primary" extends Tone ? number : string`, stays unevaluated, as a string literal is not assignable to a string enum.
- A component built by calling a function is found when that function returns one: `createIconLoader("lucide")`, whose function returns a rendering function with typed props, and `generateCalendar<Dayjs>(config)`, whose generic arrow returns a local asserted to a component type. On shadcn/ui that adds `IconLucide` and four more icon loaders; on Ant Design, `Calendar`. A call to a function that returns anything else is left out, and no longer produces a skipped-candidate note (9 fewer on Ant Design, 18 on shadcn/ui). The new `factoryResult` detection rule appears in `detectedBy`.
- A watch session applies a file change faster: it no longer spends the update freeing the revision it replaces. On a large project that was about a quarter of each change; the free now happens on another thread.
- A component re-bound from an import is found in two more forms, `const { Option } = Imported` and `const Chart = Imported`, and its props are the imported component's, also when the package declares it as a `React.MemoExoticComponent` or behind a re-exported default. On shadcn/ui that adds `ChartLegend` (four registries) and `Form`; on Ant Design, `Option`. An alias of a component the project already declares under that name is not reported twice.
- A prop written in an inline object type (`props: { ... }`) keeps its JSDoc tags, such as `@deprecated` and `@example`, as a prop in an interface already did. Before, only its description survived. A method written in an inline object type also keeps its description.
- Writing the canonical JSON is faster on a project with many diagnostics: the lists of components each diagnostic names are identified on all threads instead of one. On Chakra the write takes about 25 ms instead of 30 ms; the JSON is byte for byte the same.
- A session with `semanticTypes: 'on-demand'` no longer drops the warning that a prop's type could not be fully resolved when the checker did not return that prop. The prop keeps its structural, partly unresolved type, and its diagnostic now stays with the component instead of disappearing.
- Runs that load dependency declarations hold about 6% less memory on a project the size of shadcn/ui (330 to 313 MiB peak, output unchanged): the search for React augmentations behind a package a project imports resolves it once per directory scope, and reads the re-exports of the files it passes through without keeping their parse.
- An interface declared inside a function body, a block or a `switch` case no longer collides with an interface of the same name elsewhere in the file. Before, a module-level interface of that name replaced it, two local ones in different functions overwrote each other, and a component built by a factory showed the wrong props. Each reference now resolves to the nearest interface of its name, the way TypeScript reads it, and declarations of one name in the same scope still merge.
- A project with no `typescript` installed now gets a warning that says so, instead of `Date`, `HTMLElement` and `Promise` silently staying unexpanded, and a dependency name that is missing because a re-export cannot be resolved now names that re-export as the cause. Install `typescript` in the project to clear the warning.
- Compound components built with `Object.assign(Root, { Item })` or by assigning `Root.Item = …` are now found under their public names, with inline sub-components included, instead of being reported as the inner function or dropped without a note. No action needed.
- A prop now says why its type is partly a guess: the canonical JSON gains `degradedBy` on a prop whose type holds an opaque member, and the TOON output (`--format toon`) lists each prop's declaring type, quotes string literals in single quotes, shows the names a collapsed inherited layer declares, and adds a `degradedBy` column when a prop has one. A host that works in process can ask the session for one component as TOON with `sessionComponentToon(sessionId, key)` instead of rendering a whole project.
- A component typed `FC`, `FunctionComponent`, `ComponentType`, `Component` or `PureComponent` is found when React's type is imported under another name or through a namespace (`import { FC as Fn }`, `R.FC`), and a type of the same name imported from another module is no longer taken for React's.
- A type of your own named `K` used as the value of a `Record` now keeps its shape instead of becoming the key, and a generic parameter now shadows a module-level type of the same name everywhere it is used. No action needed.
- Removed `CollectedType::needs_type_checker` and `CollectedType::as_string_union_keys` from the public API. Nothing in the crate used either method, so there is no replacement; match on the `CollectedType` variants directly if you need the same information.
- The minimum supported Rust version is now 1.99, and the crates use edition 2024. Building from source needs Rust 1.99 or newer; prebuilt binaries and npm packages are unaffected, and the output is unchanged.
- Two interfaces with the same name in one file now merge their props, as TypeScript does, instead of the later one replacing the earlier. No action needed.

  - **Generic call props:** a component built by a generic factory takes its props from the factory's result type when that resolves, and an `export *` barrel reaches any exported value. A prop two members declare intersects, and `any` absorbs the intersection.
- - **`Exclude`, `Extract` and `NonNullable` evaluate over literal types:** `Exclude<"small" | "medium" | "large", "large"> | "default"` is the union `"small" | "medium" | "default"` (an enum in the RDT format, so a select control), as TypeScript evaluates it. They used to print as written.
  - **Template literals with number or boolean parts expand:** `` `h${1 | 2 | 3}` `` is `"h1" | "h2" | "h3"`, also inside an alias's arguments.
  - **A conditional decided by a member read evaluates:** `Payload["variant"] extends string ? … : string` takes its branch when the member's type is known, including when the payload declares no such member (Mantine's `variant` props now print their variants or `string` instead of the conditional's source).
  - **Member reads inside an alias's arguments evaluate,** through mapped types such as csstype's `Fallback<T>`: Chakra's style props print csstype's property types (`ConditionalValue<Property.Filter | … | AnyString>`) instead of `CssProperties["filter"]`.
- - **Props through conditional, indexed and mapped types:** a props type built as `T extends keyof Recipes ? Recipes[T]["__type"] : …` with a known `T`, or as a mapped type over a known type's keys (`{ [K in keyof Variant]?: … }`), now lists its props instead of a warning. Chakra's recipe props (`size`, `variant`, …) now appear: 332 of the 363 react-docgen-typescript reports on Chakra with dependencies loaded, none before.
  - **An alias argument that reads a member prints as what it reads:** `ConditionalValue<ButtonVariant["size"]>` prints `ConditionalValue<"sm" | "md" | "lg" | undefined>`, as TypeScript does.
- - **Components declared inside a function body are not documented:** a factory's returned component (`function createLeaf() { const Result = forwardRef(…); return Result; }`) or a local helper exists per call, and no module imports it by that name. Each is now an Info `SKIPPED_CANDIDATE` diagnostic instead of a component; React Spectrum's two `Result` entries and antd's local `PurePanel`, which shadowed the module-level one, are gone.
  - **Fewer skip diagnostics:** a PascalCase local that matches no component pattern (`const Comp = asChild ? Slot : "button"`) is no longer reported.
- - **A re-exported member of an imported component is documented with `--load-dependencies`:** `export const CheckboxHiddenInput = ArkCheckbox.HiddenInput` has the props of Ark's `HiddenInput` (Chakra: 11 components that react-docgen-typescript reports). Without the package loaded there is nothing to show, so it is left out. The parse cache schema moves to 21.

It is now `(event: MouseEvent<SVGSVGElement>) => void`, as TypeScript reads it.
- - **`Exclude`, `Extract` and `NonNullable` come from TypeScript's own definitions:** they were matched by name and evaluated only over literals. Now `type Exclude<T, U> = T extends U ? never : T` from the project's `lib.es5.d.ts` is evaluated the way TypeScript does, so a conditional alias over a bare type parameter distributes over the members of its argument, through aliases, `(typeof LIST)[number]` and `boolean`. A project's own `type Without<T, U> = T extends U ? never : T` works the same. `T & {}` removes `null` and `undefined`. Without TypeScript installed, these print as written, as before.
  - **A generic alias with a long expansion prints by name, as TypeScript and react-docgen-typescript do:** `Responsive<DimensionValue>` instead of its 80 literals three times over (React Spectrum: exact agreement with react-docgen-typescript's type text rises from 67.5% to 78.1%).
  - **A union drops `never` and a union of nothing is `never`.**
- - **`CSSProperties["key"]` reads csstype with `--load-dependencies`:** a prop typed `React.CSSProperties["pointerEvents"]` was always `string`, and `["zIndex"]` always `number`. With dependencies loaded, they now have csstype's types, as TypeScript does: `pointerEvents`, `objectFit` and `resize` are enums, `width` is `string | number` plus its keywords. Without dependencies, the previous answers stay.
  - **Indexed access reads the declaration first:** `Leaf["value"]` reads through `Leaf`'s ancestors in other files and binds their type arguments, and a member of a React type (`ButtonHTMLAttributes<HTMLButtonElement>["formAction"]`) reads React's declaration in curated mode. These used to print the access unevaluated or the unbound parameter.
  - **A literal-union alias inside a union contributes its members:** `Size | "xl"` is one union of literals, so the RDT format shows it as an enum, and a member it repeats is listed once. Printed text is unchanged; in `--json` the alias's members replace a nested `{"kind":"literalUnion"}`.
- - **Less memory with `--load-dependencies`:** a generic alias reference no longer resolves its arguments before expanding the alias (the expansion reads them again), and equal props built for different components are one allocation. Chakra's peak memory with dependencies loaded falls from 522 to 388 MiB. Output is unchanged.

- - **An omitted type argument takes its parameter's default:** `interface Props extends DOMAttributes` with `DOMAttributes<T = FocusableElement>` binds `T` to `FocusableElement`, as TypeScript does. Event handlers inherited from a library no longer print an unbound `MouseEvent<T>` (React Spectrum: 1,208 props), and `type Pair<A, B = A[]>` used as `Pair<string>` is `{ first: string; second: string[] }`.
  - **The parse cache schema moves to 20** (type parameter defaults are stored with each file's declarations), so existing caches are rebuilt once.
- - **A union lists each member once:** a union built from aliases that resolve to the same type prints that type once, as TypeScript does. React Spectrum's collection `children` printed `ReactNode | null | ReactNode | null | …` and now prints `ReactNode | null | (ReactNode | null)[] | …`; `T[] | readonly T[]` prints `T[]`.
  - **JSON unions are flat:** in `--json` output a union member that is an alias of a union now contributes that union's members in its place instead of a nested `{"kind":"union"}`. Printed type text is unchanged by this.
- **A wrapper-built component gets the props its factory's result type adds:** `const Button = factory<ButtonFactory>(…)` now also lists the props the type `factory` returns declares beyond the payload, such as Mantine's `component` and `renderRoot`, as react-docgen-typescript does. The factory may be reached through `export *` barrels, and editing it updates the components it builds in watch mode. On Mantine's core package, 360 missing props are now reported.

That includes through conditionals, `&&`, arrays and calls such as `items.map(i => <li/>)` or `createPortal(...)`, and a local initialized with JSX and then returned.
    - Returning `null`, `children` or a component call also counts, as does calling a hook.
    - JSX that is built but never returned, JSX only inside a nested callback, or JSX inside a returned object no longer counts. A typed helper that builds a label and returns a string is no longer a component.
  - **An element return type must be React's:** `ReactNode`, `ReactElement` or `JSX.Element` imported from React, or not imported at all. The same name imported from another module no longer makes a function a component.
  - Across the five calibration corpora this drops one component, antd's `QRcodeStatus`. It returns the result of a render function chosen at runtime, which only its type shows to be an element.
- - **`tsconfigPath` is read the way TypeScript reads it:** block and line comments, `extends`, `baseUrl` and `paths` wildcards. Before, a hand-written reader understood only line comments and ignored `extends`. Any config it could not parse silently produced no aliases, so every aliased import failed to resolve with nothing pointing at the config.
  - **A tsconfig that cannot be read or parsed is reported once,** as a warning naming the file.
  - **React Aria's `RenderProps<T>`** gives `className`, `style` and `children` as a value or a function of the render state. Before, `className` and `style` lost their function form and `children` was dropped.
  - **A parse-cache file over 256 MB is reported and ignored** rather than read into memory.
- `SKIPPED_CANDIDATE` diagnostics now report the line and column of the declaration they skipped. Before, both were empty.
- Two diagnostic codes that were overloaded now have their own. A type that references itself reports `CIRCULAR_REFERENCE` instead of `MAX_DEPTH_EXCEEDED`, which now means only that nesting was too deep. A missing `@types/react` or TypeScript lib file reports `MISSING_TYPE_LIBRARY` instead of `UNRESOLVABLE_IMPORT`. Filters on the old codes need updating. The on-disk parse cache is rebuilt once (schema 6).
- - **Writing the output is faster, with byte-identical JSON.** Mantine's full run drops from 137 to 90 ms; react-spectrum's from 93 to 71 ms. Prop types are now streamed to the serializer instead of being built as an intermediate JSON tree first.
  - The JSON key order of prop types is now fixed by the code. Before, it depended on whether a dependency enabled a `serde_json` feature.
- Type arguments are now carried as structured types instead of display text. Several props that were silently wrong now resolve correctly:
  
  - `Pick<Base, "T">` inside a generic interface keeps the key `"T"`.
  - A type named `Infinity` or `NaN` is that type.
  - Function-typed arguments resolve instead of becoming opaque.
  - `extends Required<T>` keeps `T`'s props and marks them required.
  - `extends ComponentPropsWithoutRef<typeof Button>` yields `Button`'s props instead of HTML attributes for an element called "typeof button".
  - Nested object arguments no longer raise a false circular-reference note.
  
  In `caliper-docgen-core`, `ComponentMapping::props_type_args` and `ExtendsRef`'s `type_args` are now `Vec<CollectedType>`. The on-disk parse cache is rebuilt once (schema 11).
- - **A project's own type named like a builtin is that type.** A local or imported `ReactNode`, `CSSProperties`, `Ref`, `Partial` or `Required` now resolves as declared. Before, these were matched by spelling first and read as React's or TypeScript's type, or as an empty utility. Mantine's own `CSSProperties`, which extends React's with an index signature, now appears as itself in `style` props.
  - **React meanings need React's binding; TypeScript utilities need no binding at all.** `PropsWithChildren` and `PropsWithRef` count as React's.
  - **When a builtin name is bound to something that can't be resolved,** such as a package that isn't installed, React's meaning is still used, and an `Info` `UNRESOLVABLE_IMPORT` diagnostic says so. react-spectrum's source-only mirror reports 29 of these, for types from `@react-types/shared`. Before, they were silent.
- Components written as a plain typed arrow or function expression, such as `export const Button = ({ variant }: ButtonProps) => ...`, are now detected. Async and generator functions and functions whose first parameter is not a named type are ignored. On the Ant Design source this raises component recall against react-docgen-typescript from 88% to 96%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 8).
- `Pick` and `Omit` now work when their first argument is itself generic (`Pick<Gen<number>, "x">`) and when `Omit` removes `keyof Other`. Before, a generic first argument dropped the props with no warning, and `keyof` omitted nothing. Known HTML attribute interfaces named inside these utilities no longer raise an unresolvable-type warning.
- Watch mode now agrees with a fresh extraction. The session snapshot lists enums under their public names (it exposed internal `path:name` keys), an import added by an edit is followed by later edits (the dependency graph was only built once), and a wrapper-call guess that resolves to no props is omitted the same way. The unused public `WatchSession::source_cache` field is removed.
- - **Watch output equals a cold extract.** After any edit, creation, rename or deletion, a watch session's snapshot has the same components, enums and diagnostics as `extract` over the same files. Before, edits to a dependency reached through a barrel or a `../` import were missed, deleted files' components stayed until restart, excluded files such as stories added components, a disambiguated component's edit could land under another component's key, and the first run's diagnostics were dropped from later snapshots.
  - **Precise re-resolution.** Each component records the files, project-wide names and module resolutions its props depended on; a change re-resolves exactly the components it can affect.
  - **`IncrementalUpdate` gains `revision`, `updatedKeys` and `removedKeys`,** so a consumer can apply an update to a keyed map and drop removed entries.
  - **Breaking (Rust API):** `WatchSession`'s fields other than `options` and the `ReverseDeps` type are removed; `WatchSession::rebuild()` is new. A deleted file is now a removal, not an `IoError`.
  - Resolve diagnostics are ordered by file and source position.
- Components built by a wrapper call whose props travel as a type argument are now detected, for example `const Button = polymorphicFactory<ButtonFactory>(...)` where `ButtonFactory` is `Factory<{ props: ButtonProps }>`, or `const Item = withContext<HTMLDivElement, ItemProps>("div")`. Detection is by shape, not by library name: a PascalCase binding initialized with a generic call whose first argument is a function, a tag name or a reference, with the props type picked from the type arguments. Element and ref types are skipped, and a guess whose props resolve to nothing is reported as a `SKIPPED_CANDIDATE` note instead of being listed. On the Mantine source this raises component recall against react-docgen-typescript from 29% to 82%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 9).

## 0.2.0

- Ambient `.d.ts` files are merged for their types only, never their components. `@types/react` declares `class PureComponent<P, S, SS> extends Component<P, S, SS>`, which matched the class-component detector — full HTML-attribute mode emitted `PureComponent` as a 0-prop component alongside a `Cannot resolve type 'P'` diagnostic. Both are gone, from batch extraction and from the watch session's first revision.
- A prop redeclared in a child interface now replaces the inherited one. `interface Child extends Base { x: "a" | "b" }` used to resolve `x` to `Base`'s type, description and parent. An undocumented redeclaration keeps the inherited description, as react-docgen-typescript does.
- Lint policy (`unsafe_code`, clippy `all`) moved from per-crate `#![...]` attributes into a single `[workspace.lints]` table in the workspace root, with each crate opting in via `[lints] workspace = true`. `unsafe_code` is now `"deny"` rather than `"forbid"` — no crate currently uses `unsafe`, including the NAPI FFI boundary, but `deny` allows a local `#[allow(unsafe_code)]` override if one is ever genuinely needed there.
  
  Also dropped 11 dependencies that `cargo-machete` confirmed were unused: `indexmap`, `oxc_module_lexer`, `thiserror`, `tokio`, `dirs`, `miette` (core); `anyhow`, `clap_mangen`, `lsp-types`, `tracing-indicatif` (cli); `rustc-hash` (binding). No behavior change — smaller dependency graph and faster builds.
- Concurrent runs sharing one DTS cache directory — the CLI and the Vite plugin in the same project, or parallel builds — no longer report a spurious `IO_ERROR` "Failed to persist the DTS cache" diagnostic. Every writer used the same temp file name, so the second rename found it already moved. Temp names are now unique per process and write.
- First public release. React component prop extraction on OXC, with no TypeScript `Program` and no type-checking pass: cold extraction across 21 real component libraries in about 50ms and ~2ms for an incremental single-file update.
  
  - `caliper-docgen` CLI with `--format canonical | rdt | toon`, `docgen.config.ts` loading, watch mode, and a `schema` subcommand that exports the component metadata as a Draft-07 JSON Schema. `--format rdt` emits a `react-docgen-typescript`-compatible shape (see `MIGRATING.md`); `--format toon` is a token-optimized output for LLM agents.
  - Cross-package `.d.ts` resolution with an atomic, bounded on-disk cache, and a plugin system (`DocgenPlugin` / `PluginRegistry`) for AST and component resolution hooks.
  - NAPI binding and a Vite plugin that expose the canonical format.
  - An `lsp` subcommand scaffold with bounded framing and the initialize/shutdown/exit lifecycle. It does not serve prop hovers yet.
- Fixed 7 doc-comment errors that broke `cargo doc` under `-D warnings`: 6 unescaped angle-bracket type names (`Ref<T>`, `RefObject<T>`, `HTMLButtonElement`, etc.) that rustdoc parsed as unclosed HTML tags, and one `[default]` that rustdoc parsed as a broken intra-doc link. No behavior change — fixes how the published crate's documentation renders on docs.rs.
- An unrecognized `htmlAttributes` value (a typo in `docgen.config.ts` or in the JS options) is now an error naming the value, instead of silently falling back to `curated`, as `reactVersion` already does.
- String-literal union aliases now report bare member values. A `type Size = "sm" | "md"` alias previously came back with each member already quoted, so serialized output showed `""sm"" | ""md""` and a template literal over the alias expanded to `compact-"sm"`. `undefined` members are dropped (optionality is reported through `required`); a `null` member keeps the alias a plain union, since a string-only literal union can't represent it.
  
  The DTS cache schema version moved to 4 — its key is a content hash and can't detect that the extractor now produces different data for identical input, so existing cache files are discarded rather than served stale.
- DOM and ES globals (`HTMLDivElement["dir"]`, `Date`, …) resolve again in projects on TypeScript 7, which moved `lib.dom.d.ts`/`lib.es5.d.ts` into its per-platform `@typescript/typescript-*` package. A `typescript` install whose lib files can't be found (TypeScript 7 without its optional platform package) now warns instead of silently leaving those globals unexpanded.
- `WatchSession::update_file` now reports a re-read file's syntax errors and other parse diagnostics, as a cold extraction does. An edit that broke a file used to produce no diagnostic at all, so `watch` showed nothing and its exit code stayed 0.
