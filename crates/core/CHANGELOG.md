# caliper-docgen-core

## 0.3.0

- - **A parse cache written by any other build is discarded.** The cache file now starts with the schema version, the crate version and a fingerprint of the code that produces it; any mismatch rebuilds the cache. Before, extractor changes that kept the cached data's shape served stale `.d.ts` results until someone remembered to bump a version, and two tool versions sharing a cache directory could read each other's data.
  - A cache from this build that cannot be decoded is reported with an `Info` diagnostic, then rebuilt.
  - **`stats.dtsFilesParsed` and `stats.dtsCacheHits` count every `.d.ts` file the run used,** including TypeScript's own lib files. Before, they counted only `.d.ts` files inside the source directories, so they usually read 0.
  - The cache file is now `dts.msgpack`; an old `dts-v1.msgpack` is ignored and can be deleted.
- - **`watch --out` is written at startup,** not only after the first change, so a consumer reading it never waits on an edit.
  - **`r` extracts everything again** and rewrites `--out`, for changes the file watcher cannot see such as `tsconfig.json`, `package.json` or `node_modules`. Before, it only refreshed the exit code.
  - **An event that changes nothing** (a non-TypeScript or excluded file) no longer rewrites `--out`.
  - **Removed components are reported** on change.
  - **Output lines in an interactive session start at column 0.** Raw mode had turned off newline translation, so every printed line began where the last one ended.
  - `WatchSession::revision()` returns the published revision number.
- - **Default exports:** anonymous default-exported components are detected and named after their file: `export default (props: P) => …`, `export default memo(function Badge(…))`, `export default forwardRef<El, P>(…)` and `export default class extends Component<P>`.
  - **Wrapper types:** `Required<P>` as a props type marks P's props required, and `PropsWithChildren<P>` adds a `children` prop.
  - **Excludes:** the built-in `.test.`, `.spec.`, `.stories.`, `__snapshots__` and `node_modules` checks, and user excludes, now apply to the path inside each source directory. Before, a project checked out under a directory such as `my.test.repo` produced no components and no warning.
- - **Applying every watch update in order now reproduces the snapshot exactly.**
    - `updatedKeys` includes components whose key moved because a same-named component elsewhere appeared or disappeared. Before, a client applying updates kept a stale entry under the moved key.
    - **Breaking:** `IncrementalUpdate.diagnostics` now holds only the diagnostics a change added; the new `removedDiagnostics` lists the ones it removed. Before, it re-sent the changed file's current diagnostics, and fixed diagnostics never left a client's list.
  - **The Vite plugin applies and announces changes one at a time,** so `caliper-docgen:update` events arrive in revision order across files. `CaliperDocgenUpdate` gains `removedDiagnostics`.
- - **Each component reports how it was recognized:** `detectedBy` is one of `functionDeclaration`, `forwardRef`, `fcAnnotation`, `hocWrapper`, `classComponent`, `forwardRefExoticDecl`, `anonymousDefaultExport`, `attachedSubComponent`, `typedFunctionExpression` or `wrapperTypeArgument`. The last two are inferred from a function's shape and what it returns; the rest are explicit declaration forms. It is in the JSON output, the JSON schema and the TypeScript types.
  - **Breaking (Rust API):** `ComponentEntry` gains a public `detected_by` field, and `DetectionRule` serializes in camelCase. The parse cache schema moves to 14.
- Component detection now needs evidence that something renders, so typed helpers, selectors, contexts and stores no longer appear as components:
  
  - **Functions:** a PascalCase function with a typed props parameter must contain JSX or an element factory call, call a hook, return `null`, `children` or a component call, or declare an element return type. That covers arrows, function expressions, functions wrapped in a call, and function declarations. `FormatName = (u: User) => string`, `debounce((q: Row) => …)` and generators are now declined with a `SKIPPED_CANDIDATE` note that says why.
  - **Generic wrapper calls** (`factory<F>(…)`, `withContext<El, P>("div")`): the first argument must be a function that renders, a component reference, a wrapped component, or a tag name next to an element type or factory payload. `createContext`, `createStore`, `makeLabel<P>("button")` and similar are declined.
  - **`.d.ts` declarations:** `declare function Button(props: P): JSX.Element` is now detected.
  - **Async server components** are detected.
  - **Aliases:** `memo(Card)` no longer hides an exported `Card`. A call that doesn't look like a component wrapper (`getDisplayName(Card)`) is no longer a component.
  - **Unresolvable props:** a wrapper component whose props live in an uninstalled package is kept instead of dropped. This restores 81 Chakra components.
- `ComponentMapping` now records which extractor rule matched it (`DetectionRule`), and `ComponentMapping::new` takes it as a required argument. The on-disk parse cache is rebuilt once (schema 7).
- Two files that export an enum with the same name now give the same output on every run: the first file path in sorted order wins, and a `DUPLICATE_ENUM_NAME` warning names both files. Before, hash order picked the winner and nothing was reported. Enum keys on Windows paths are also split correctly. The on-disk parse cache is rebuilt once (schema 5).
- - **Each diagnostic is reported once.** Identical diagnostics from many components merge into one, with a new `affects` field listing those components' output keys. Mantine's output drops from 24,009 diagnostics to 563 and from 24 MB to 15.6 MB; chakra-ui drops from 4,538 to 583 diagnostics.
  - **Diagnostics are sorted** by file, line, column and message, with errors before warnings at the same spot.
  - **`IncrementalUpdate.diagnostics`** holds the changed file's diagnostics plus those of every re-resolved component.
  - **CLI:** the `×N` counts still count affected components.
  - **Help text:** indexed-access and template-literal diagnostics no longer tell users to "enable typescript-go", which is not an option.
  - **Breaking (Rust API):** `Diagnostic` has a new public `affects` field, so struct literals need it; `Diagnostic::new` is unaffected. `Diagnostic`, `DiagnosticSeverity` and `DiagnosticCode` now implement `Eq` and `Hash`.
- An interface that extends a type imported through a barrel file (`import type { UnstyledProp } from "../styled-system"` where `index.ts` re-exports it) now picks up that type's props. Before, the barrel was treated as the declaring file, so the props were dropped with an `UNRESOLVABLE_IMPORT` warning. On the Mantine and Chakra sources this raises the share of react-docgen-typescript's own props that Caliper reports from 13% and 18% to 86% and 85%.
- - **A generic type alias used as a prop's type takes its arguments.** `size: StyleProp<MantineSize>` now resolves to `MantineSize | MantineSize[]`. Before, it resolved to the alias's own parameter name (`Value | Value[]`), as though `Value` were a type.
  - Leaked parameter names in prop types drop from 25,624 to 72 on Mantine, 721 to 111 on react-spectrum, and 23 to 4 on chakra-ui. What remains is mostly generic components' own type parameters, which react-docgen-typescript also leaves unresolved.
  - Mantine's `classNames` keys become the real selector names, and MUI's `sx` callbacks name `Theme`.
- Two props-resolution gaps are closed. A generic interface now receives its type arguments: `Box<string>` for `interface Box<T> { value: T }` yields `value: string`, including through the interface's own `extends Box<T[]>`; before, `value` stayed the unresolved placeholder `T`. And a barrel file written as `import type { X } from "./x"; export type { X };` is now followed like `export type { X } from "./x"`; before, anything imported through such a barrel failed to resolve. On the Mantine source this raises the share of react-docgen-typescript's own props that Caliper reports from 87% to 92%.
- - **Breaking (canonical JSON):** each distinct prop is written once, in a top-level `props` table, and a component's `props` and `notableInherited` map each prop name to an id (16 hex digits). Read a prop as `output.props[output.components[key].props[name]]`. The same prop has the same id in every output and update of a build. Mantine's output drops from 19.3 MB to 3.6 MB and parses 7× faster. This covers `extract --json`, `--format canonical`, the NAPI functions and the Vite plugin's virtual module; `--format rdt` and `--format storybook` keep props inline.
  - **Breaking (watch updates):** an update carries `props` with every prop its `updatedComponents` refer to. Merge it into the output's table; ids no component refers to can be dropped. The Vite plugin's `caliper-docgen:update` event carries it too.
- - **Faster extraction on large projects:** resolved components move into the output instead of being copied, the canonical JSON is written in parallel, and the CLI uses mimalloc. Mantine extracts in 41 ms instead of 83 ms and Spectrum in 47 ms instead of 63 ms, with identical output.
  - **Fix:** `--out` to a device or FIFO such as `/dev/null` failed with a permission error, because the atomic write staged its temp file in `/dev`. Such targets are now written in place.
- Package metadata and license. The crates and npm packages now carry repository, homepage, documentation and keyword fields and a README, so crates.io, docs.rs and npmjs.com link back to the project. Starting with this release the license is FSL-1.1-MIT (each version becomes MIT two years after its release); 0.2.1 and earlier stay AGPL-3.0-or-later.
- Components wrapped in parentheses or a trailing `!`, such as `export const Button = (forwardRef<El, Props>(...))`, are now detected. They were silently skipped before.
- `Pick` and `Omit` now understand any key expression TypeScript code commonly uses: string literals and unions of them, a key alias (`type Keys = "a" | "b"`), `keyof Other`, `Exclude<…>` and `Extract<…>`, a mix such as `"a" | More`, and keys passed through a generic parameter. Before, an alias key set picked nothing or omitted nothing, silently. When the keys can't be known statically, a warning says so. The base can also be any type now, including an intersection such as `Omit<A & B, "k">`. In `caliper-docgen-core`, `CollectedTypeAlias::Pick` and `::Omit` carry a structured `keys` type instead of key lists. The on-disk parse cache is rebuilt once (schema 12).
- The minimum supported Rust version is now 1.97, which is what the OXC 0.154 parser already required. The previously declared 1.94 never built.
- Removed eight options that were accepted but never used: `reactVersion`, `crossPackage`, `pandacssOutdir`, `variantFunctions`, `vanillaExtract`, `resolveComplexTypes`, `extraPaths` and `knownTypeOverrides`. This also removes the CLI flags `--react-version` and `--no-cross-package`, and the `reactVersion` option of the Vite plugin. A `docgen.config.ts` that still names one now fails with an error naming the field, instead of looking honored. Extraction output is unchanged.
- An unreadable `@types/react` or TypeScript lib file now raises an `IO_ERROR` diagnostic instead of being parsed as an empty file and cached that way. `--format rdt` and `--format storybook` now exit with an error if serialization fails instead of printing nothing.
- - **Cold extraction is 19–35% faster** with identical output. On the calibration corpora: react-spectrum 150 → 97 ms, Mantine 180 → 146 ms, shadcn 68 → 51 ms, chakra-ui 33 → 25 ms, Ant Design 44 → 34 ms.
    - Each import specifier is resolved once per directory instead of once per component.
    - Hot lookups key on the path string instead of hashing a path component by component.
    - Discovery walks in parallel and only canonicalizes symlinks.
  - An import that resolves to a non-UTF-8 path now reports an `UNRESOLVABLE_IMPORT` diagnostic instead of being dropped silently.
- - **A function counts as a component only if it returns an element.** Its own `return`s, or its arrow body, must hold JSX or an element factory call. That includes through conditionals, `&&`, arrays and calls such as `items.map(i => <li/>)` or `createPortal(...)`, and a local initialized with JSX and then returned.
    - Returning `null`, `children` or a component call also counts, as does calling a hook.
    - JSX that is built but never returned, JSX only inside a nested callback, or JSX inside a returned object no longer counts. A typed helper that builds a label and returns a string is no longer a component.
  - **An element return type must be React's:** `ReactNode`, `ReactElement` or `JSX.Element` imported from React, or not imported at all. The same name imported from another module no longer makes a function a component.
  - Across the five calibration corpora this drops one component, antd's `QRcodeStatus`. It returns the result of a render function chosen at runtime, which only its type shows to be an element.
- - **`tsconfigPath` is read the way TypeScript reads it:** block and line comments, `extends`, `baseUrl` and `paths` wildcards. Before, a hand-written reader understood only line comments and ignored `extends`. Any config it could not parse silently produced no aliases, so every aliased import failed to resolve with nothing pointing at the config.
  - **A tsconfig that cannot be read or parsed is reported once,** as a warning naming the file.
  - **React Aria's `RenderProps<T>`** gives `className`, `style` and `children` as a value or a function of the render state. Before, `className` and `style` lost their function form and `children` was dropped.
  - **A parse-cache file over 256 MB is reported and ignored** rather than read into memory.
- `SKIPPED_CANDIDATE` diagnostics now report the line and column of the declaration they skipped. Before, both were empty.
- Two diagnostic codes that were overloaded now have their own. A type that references itself reports `CIRCULAR_REFERENCE` instead of `MAX_DEPTH_EXCEEDED`, which now means only that nesting was too deep. A missing `@types/react` or TypeScript lib file reports `MISSING_TYPE_LIBRARY` instead of `UNRESOLVABLE_IMPORT`. Filters on the old codes need updating. The on-disk parse cache is rebuilt once (schema 6).
- - **Writing the output is faster, with byte-identical JSON.** Mantine's full run drops from 137 to 90 ms; react-spectrum's from 93 to 71 ms. Prop types are now streamed to the serializer instead of being built as an intermediate JSON tree first.
  - The JSON key order of prop types is now fixed by the code. Before, it depended on whether a dependency enabled a `serde_json` feature.
- Type arguments are now carried as structured types instead of display text. Several props that were silently wrong now resolve correctly:
  
  - `Pick<Base, "T">` inside a generic interface keeps the key `"T"`.
  - A type named `Infinity` or `NaN` is that type.
  - Function-typed arguments resolve instead of becoming opaque.
  - `extends Required<T>` keeps `T`'s props and marks them required.
  - `extends ComponentPropsWithoutRef<typeof Button>` yields `Button`'s props instead of HTML attributes for an element called "typeof button".
  - Nested object arguments no longer raise a false circular-reference note.
  
  In `caliper-docgen-core`, `ComponentMapping::props_type_args` and `ExtendsRef`'s `type_args` are now `Vec<CollectedType>`. The on-disk parse cache is rebuilt once (schema 11).
- - **A project's own type named like a builtin is that type.** A local or imported `ReactNode`, `CSSProperties`, `Ref`, `Partial` or `Required` now resolves as declared. Before, these were matched by spelling first and read as React's or TypeScript's type, or as an empty utility. Mantine's own `CSSProperties`, which extends React's with an index signature, now appears as itself in `style` props.
  - **React meanings need React's binding; TypeScript utilities need no binding at all.** `PropsWithChildren` and `PropsWithRef` count as React's.
  - **When a builtin name is bound to something that can't be resolved,** such as a package that isn't installed, React's meaning is still used, and an `Info` `UNRESOLVABLE_IMPORT` diagnostic says so. react-spectrum's source-only mirror reports 29 of these, for types from `@react-types/shared`. Before, they were silent.
- Components written as a plain typed arrow or function expression, such as `export const Button = ({ variant }: ButtonProps) => ...`, are now detected. Async and generator functions and functions whose first parameter is not a named type are ignored. On the Ant Design source this raises component recall against react-docgen-typescript from 88% to 96%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 8).
- `Pick` and `Omit` now work when their first argument is itself generic (`Pick<Gen<number>, "x">`) and when `Omit` removes `keyof Other`. Before, a generic first argument dropped the props with no warning, and `keyof` omitted nothing. Known HTML attribute interfaces named inside these utilities no longer raise an unresolvable-type warning.
- Watch mode now agrees with a fresh extraction. The session snapshot lists enums under their public names (it exposed internal `path:name` keys), an import added by an edit is followed by later edits (the dependency graph was only built once), and a wrapper-call guess that resolves to no props is omitted the same way. The unused public `WatchSession::source_cache` field is removed.
- - **Watch output equals a cold extract.** After any edit, creation, rename or deletion, a watch session's snapshot has the same components, enums and diagnostics as `extract` over the same files. Before, edits to a dependency reached through a barrel or a `../` import were missed, deleted files' components stayed until restart, excluded files such as stories added components, a disambiguated component's edit could land under another component's key, and the first run's diagnostics were dropped from later snapshots.
  - **Precise re-resolution.** Each component records the files, project-wide names and module resolutions its props depended on; a change re-resolves exactly the components it can affect.
  - **`IncrementalUpdate` gains `revision`, `updatedKeys` and `removedKeys`,** so a consumer can apply an update to a keyed map and drop removed entries.
  - **Breaking (Rust API):** `WatchSession`'s fields other than `options` and the `ReverseDeps` type are removed; `WatchSession::rebuild()` is new. A deleted file is now a removal, not an `IoError`.
  - Resolve diagnostics are ordered by file and source position.
- Components built by a wrapper call whose props travel as a type argument are now detected, for example `const Button = polymorphicFactory<ButtonFactory>(...)` where `ButtonFactory` is `Factory<{ props: ButtonProps }>`, or `const Item = withContext<HTMLDivElement, ItemProps>("div")`. Detection is by shape, not by library name: a PascalCase binding initialized with a generic call whose first argument is a function, a tag name or a reference, with the props type picked from the type arguments. Element and ref types are skipped, and a guess whose props resolve to nothing is reported as a `SKIPPED_CANDIDATE` note instead of being listed. On the Mantine source this raises component recall against react-docgen-typescript from 29% to 82%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 9).

## 0.2.1

- First release under the Caliper names. The crates, the CLI binary and the npm packages were published as `oxc-react-docgen*` before, and are now `caliper-docgen`, `caliper-docgen-core`, `caliper-docgen-napi`, `caliper-docgen-vite-plugin` and their platform packages. The Vite plugin export is `caliperDocgen`. Nothing else changes.

## 0.2.0

- Ambient `.d.ts` files are merged for their types only, never their components. `@types/react` declares `class PureComponent<P, S, SS> extends Component<P, S, SS>`, which matched the class-component detector — full HTML-attribute mode emitted `PureComponent` as a 0-prop component alongside a `Cannot resolve type 'P'` diagnostic. Both are gone, from batch extraction and from the watch session's first revision.
- A prop redeclared in a child interface now replaces the inherited one. `interface Child extends Base { x: "a" | "b" }` used to resolve `x` to `Base`'s type, description and parent. An undocumented redeclaration keeps the inherited description, as react-docgen-typescript does.
- Lint policy (`unsafe_code`, clippy `all`) moved from per-crate `#![...]` attributes into a single `[workspace.lints]` table in the workspace root, with each crate opting in via `[lints] workspace = true`. `unsafe_code` is now `"deny"` rather than `"forbid"` — no crate currently uses `unsafe`, including the NAPI FFI boundary, but `deny` allows a local `#[allow(unsafe_code)]` override if one is ever genuinely needed there.
  
  Also dropped 11 dependencies that `cargo-machete` confirmed were unused: `indexmap`, `oxc_module_lexer`, `thiserror`, `tokio`, `dirs`, `miette` (core); `anyhow`, `clap_mangen`, `lsp-types`, `tracing-indicatif` (cli); `rustc-hash` (binding). No behavior change — smaller dependency graph and faster builds.
- Concurrent runs sharing one DTS cache directory — the CLI and the Vite plugin in the same project, or parallel builds — no longer report a spurious `IO_ERROR` "Failed to persist the DTS cache" diagnostic. Every writer used the same temp file name, so the second rename found it already moved. Temp names are now unique per process and write.
- First public release. React component prop extraction on OXC, with no TypeScript `Program` and no type-checking pass: cold extraction across 21 real component libraries in about 50ms and ~2ms for an incremental single-file update.
  
  - `caliper-docgen` CLI with `--format canonical | rdt | toon`, `docgen.config.ts` loading, watch mode, and a `schema` subcommand that exports the component metadata as a Draft-07 JSON Schema. `--format rdt` emits a `react-docgen-typescript`-compatible shape (see `MIGRATING.md`); `--format toon` is a token-optimized output for LLM agents.
  - Cross-package `.d.ts` resolution with an atomic, bounded on-disk cache, and a plugin system (`DocgenPlugin` / `PluginRegistry`) for AST and component resolution hooks.
  - NAPI binding and a Vite plugin that expose the canonical format.
  - An `lsp` subcommand scaffold with bounded framing and the initialize/shutdown/exit lifecycle. It does not serve prop hovers yet.
- Fixed 7 doc-comment errors that broke `cargo doc` under `-D warnings`: 6 unescaped angle-bracket type names (`Ref<T>`, `RefObject<T>`, `HTMLButtonElement`, etc.) that rustdoc parsed as unclosed HTML tags, and one `[default]` that rustdoc parsed as a broken intra-doc link. No behavior change — fixes how the published crate's documentation renders on docs.rs.
- An unrecognized `htmlAttributes` value (a typo in `docgen.config.ts` or in the JS options) is now an error naming the value, instead of silently falling back to `curated`, as `reactVersion` already does.
- String-literal union aliases now report bare member values. A `type Size = "sm" | "md"` alias previously came back with each member already quoted, so serialized output showed `""sm"" | ""md""` and a template literal over the alias expanded to `compact-"sm"`. `undefined` members are dropped (optionality is reported through `required`); a `null` member keeps the alias a plain union, since a string-only literal union can't represent it.
  
  The DTS cache schema version moved to 4 — its key is a content hash and can't detect that the extractor now produces different data for identical input, so existing cache files are discarded rather than served stale.
- DOM and ES globals (`HTMLDivElement["dir"]`, `Date`, …) resolve again in projects on TypeScript 7, which moved `lib.dom.d.ts`/`lib.es5.d.ts` into its per-platform `@typescript/typescript-*` package. A `typescript` install whose lib files can't be found (TypeScript 7 without its optional platform package) now warns instead of silently leaving those globals unexpanded.
- `WatchSession::update_file` now reports a re-read file's syntax errors and other parse diagnostics, as a cold extraction does. An edit that broke a file used to produce no diagnostic at all, so `watch` showed nothing and its exit code stayed 0.
