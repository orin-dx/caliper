# caliper-docgen-vite-plugin

## 0.5.0

- **Curated mode also gives a prop beside `ComponentProps<"div">` the element attribute's type:** recharts' `onTimeUpdate` next to a div's attributes is now `ReactEventHandler<HTMLDivElement>` intersected with recharts' handler in the default curated mode too, not only in Full mode. Curated mode reads React's declarations for this lookup only (ADR 0013), so nothing else in its output changes.
- - **A library's own declaration wins over a built-in shortcut:** with `--load-dependencies`, a component typed with `HTMLChakraProps<"div">` or Chakra's `ButtonProps` gets the library's real props (139 and 146 of react-docgen-typescript's, against 1 and 0 before), and Mantine's `StylesApiProps` its 8. Shortcuts remain only as fallbacks: when the package isn't loaded, or when its declaration needs a type checker (cva's `VariantProps`).
  - **Fewer library shortcuts:** `SxProps`, `SystemStyleObject`, `SystemCssProperties`, `OverridableStringUnion`, `ThemingProps` and `StylesApiProps` are no longer special-cased. Without their package loaded they stay named references with an `UNRESOLVABLE_IMPORT` warning, like any other uninstalled type; `sxProps` is no longer emitted as a type kind.
  - **Generic call props:** a component built by a generic factory takes its props from the factory's result type when that resolves, and an `export *` barrel reaches any exported value. A prop two members declare intersects, and `any` absorbs the intersection.
- - **`Exclude`, `Extract` and `NonNullable` evaluate over literal types:** `Exclude<"small" | "medium" | "large", "large"> | "default"` is the union `"small" | "medium" | "default"` (an enum in the RDT format, so a select control), as TypeScript evaluates it. They used to print as written.
  - **Template literals with number or boolean parts expand:** `` `h${1 | 2 | 3}` `` is `"h1" | "h2" | "h3"`, also inside an alias's arguments.
  - **A conditional decided by a member read evaluates:** `Payload["variant"] extends string ? … : string` takes its branch when the member's type is known, including when the payload declares no such member (Mantine's `variant` props now print their variants or `string` instead of the conditional's source).
  - **Member reads inside an alias's arguments evaluate,** through mapped types such as csstype's `Fallback<T>`: Chakra's style props print csstype's property types (`ConditionalValue<Property.Filter | … | AnyString>`) instead of `CssProperties["filter"]`.
- - **Props through conditional, indexed and mapped types:** a props type built as `T extends keyof Recipes ? Recipes[T]["__type"] : …` with a known `T`, or as a mapped type over a known type's keys (`{ [K in keyof Variant]?: … }`), now lists its props instead of a warning. Chakra's recipe props (`size`, `variant`, …) now appear: 332 of the 363 react-docgen-typescript reports on Chakra with dependencies loaded, none before.
  - **An alias argument that reads a member prints as what it reads:** `ConditionalValue<ButtonVariant["size"]>` prints `ConditionalValue<"sm" | "md" | "lg" | undefined>`, as TypeScript does.
- - **Components declared inside a function body are not documented:** a factory's returned component (`function createLeaf() { const Result = forwardRef(…); return Result; }`) or a local helper exists per call, and no module imports it by that name. Each is now an Info `SKIPPED_CANDIDATE` diagnostic instead of a component; React Spectrum's two `Result` entries and antd's local `PurePanel`, which shadowed the module-level one, are gone.
  - **Fewer skip diagnostics:** a PascalCase local that matches no component pattern (`const Comp = asChild ? Slot : "button"`) is no longer reported.
- - **A re-exported member of an imported component is documented with `--load-dependencies`:** `export const CheckboxHiddenInput = ArkCheckbox.HiddenInput` has the props of Ark's `HiddenInput` (Chakra: 11 components that react-docgen-typescript reports). Without the package loaded there is nothing to show, so it is left out. The parse cache schema moves to 21.
- - **Inherited React event handlers take their element:** with `--html-attributes full`, a component extending `React.SVGProps<SVGSVGElement>` or `ButtonHTMLAttributes<HTMLButtonElement>` listed `onClick` as `(event: MouseEvent<T>) => void`, with React's type parameter unbound. It is now `(event: MouseEvent<SVGSVGElement>) => void`, as TypeScript reads it.
- - **`Exclude`, `Extract` and `NonNullable` come from TypeScript's own definitions:** they were matched by name and evaluated only over literals. Now `type Exclude<T, U> = T extends U ? never : T` from the project's `lib.es5.d.ts` is evaluated the way TypeScript does, so a conditional alias over a bare type parameter distributes over the members of its argument, through aliases, `(typeof LIST)[number]` and `boolean`. A project's own `type Without<T, U> = T extends U ? never : T` works the same. `T & {}` removes `null` and `undefined`. Without TypeScript installed, these print as written, as before.
  - **A generic alias with a long expansion prints by name, as TypeScript and react-docgen-typescript do:** `Responsive<DimensionValue>` instead of its 80 literals three times over (React Spectrum: exact agreement with react-docgen-typescript's type text rises from 67.5% to 78.1%).
  - **A union drops `never` and a union of nothing is `never`.**
- - **`CSSProperties["key"]` reads csstype with `--load-dependencies`:** a prop typed `React.CSSProperties["pointerEvents"]` was always `string`, and `["zIndex"]` always `number`. With dependencies loaded, they now have csstype's types, as TypeScript does: `pointerEvents`, `objectFit` and `resize` are enums, `width` is `string | number` plus its keywords. Without dependencies, the previous answers stay.
  - **Indexed access reads the declaration first:** `Leaf["value"]` reads through `Leaf`'s ancestors in other files and binds their type arguments, and a member of a React type (`ButtonHTMLAttributes<HTMLButtonElement>["formAction"]`) reads React's declaration in curated mode. These used to print the access unevaluated or the unbound parameter.
  - **A literal-union alias inside a union contributes its members:** `Size | "xl"` is one union of literals, so the RDT format shows it as an enum, and a member it repeats is listed once. Printed text is unchanged; in `--json` the alias's members replace a nested `{"kind":"literalUnion"}`.
- - **Less memory with `--load-dependencies`:** a generic alias reference no longer resolves its arguments before expanding the alias (the expansion reads them again), and equal props built for different components are one allocation. Chakra's peak memory with dependencies loaded falls from 522 to 388 MiB. Output is unchanged.
- **String defaults keep their source quotes:** `({ size = 'md' })` gives the default `'md'`, not `"md"`, in every output format, as react-docgen-typescript and Storybook's React docgen print it. A double-quoted or template-literal default keeps its own quotes too.
- - **An omitted type argument takes its parameter's default:** `interface Props extends DOMAttributes` with `DOMAttributes<T = FocusableElement>` binds `T` to `FocusableElement`, as TypeScript does. Event handlers inherited from a library no longer print an unbound `MouseEvent<T>` (React Spectrum: 1,208 props), and `type Pair<A, B = A[]>` used as `Pair<string>` is `{ first: string; second: string[] }`.
  - **The parse cache schema moves to 20** (type parameter defaults are stored with each file's declarations), so existing caches are rebuilt once.
- - **A union lists each member once:** a union built from aliases that resolve to the same type prints that type once, as TypeScript does. React Spectrum's collection `children` printed `ReactNode | null | ReactNode | null | …` and now prints `ReactNode | null | (ReactNode | null)[] | …`; `T[] | readonly T[]` prints `T[]`.
  - **JSON unions are flat:** in `--json` output a union member that is an alias of a union now contributes that union's members in its place instead of a nested `{"kind":"union"}`. Printed type text is unchanged by this.
- **A wrapper-built component gets the props its factory's result type adds:** `const Button = factory<ButtonFactory>(…)` now also lists the props the type `factory` returns declares beyond the payload, such as Mantine's `component` and `renderRoot`, as react-docgen-typescript does. The factory may be reached through `export *` barrels, and editing it updates the components it builds in watch mode. On Mantine's core package, 360 missing props are now reported.

## 0.4.0

- - **Aliases over conditional or mapped types keep their names:** a prop typed `StyleProp<MantineSpacing>` or `MantineBreakpoint` used to print the alias's expansion, including conditional-type source such as `MantineThemeSizesOverride extends { ... } ? CustomSpacing : …`. It now prints the alias name with its arguments as written, the way TypeScript does. Aliases to literal unions and objects still expand, so enum controls are unchanged.
- - **Functions used only as functions are no longer reported as components:** a PascalCase function that returns JSX but is only ever called in its file (`ArrayType(type)`), or that takes a second parameter such as a ref and is never rendered or passed to a component wrapper (a render callback like `{render: TableDropIndicatorWrapper}`), is now a skipped candidate with the reason. Exported functions are unaffected. On React Spectrum this removes 25 false components.
- - **Large inherited sources collapse to one layer:** with `--load-dependencies`, a type from a package that contributes more than 30 props is listed as an inherited layer with its prop count and its notable props (`onClick`, `className`, `aria-label`, …) instead of prop by prop, as Storybook shows it. shadcn's components list 7,447 props instead of 12,937. `--collapse-inherited-props` (config, NAPI and Vite `collapseInheritedProps`) chooses `dependencies` (default), `all` (the project's own large sources too: chakra's repository goes from 398,915 props and 27.6 MB to 5,541 and 13.6 MB) or `none`. A component's own props type, a `Pick` from a large source and `keyof` are never collapsed. Without `--load-dependencies` the default changes nothing.
- - **`ComponentProps<typeof Button>` as a component's props resolves to `Button`'s props:** it used to look for a type named `Button` and find nothing, leaving the component with no props (shadcn's `PaginationNext` and `PaginationPrevious`, and any wrapper written this way). It now finds the component, whether it's declared in the same file, imported, or a member of an imported namespace, as the same reference already did in an `extends` clause. `ComponentPropsWithoutRef` and `ComponentPropsWithRef` work the same way; a project's own `ComponentProps` type is unaffected.
- - **Every component says whether its module exports it:** `ComponentEntry` gains `exported`. A component counts as exported when it is an exported declaration, a local named by `export { X as Y }` or `export default X`, an anonymous default export, or a sub-component attached to an exported component (`Parent.Sub = Sub`, `Object.assign(Parent, { Sub })`, `const Parent = Object.assign(Root, { Sub })`).
  - **`--format rdt` and `--format storybook` omit unexported components by default**, as react-docgen-typescript documents only exports. Pass `--include-unexported` to keep them. Canonical output keeps every component. Measured: Mantine 7 of 346 unexported, Chakra 2 of 600, shadcn 99 of 1,884, Ant Design 42 of 253, React Spectrum 194 of 1,359.
  - The DTS cache schema moves to 15, so existing caches are rebuilt once.
- - **Factory payloads with generic props:** a component built from a factory payload whose `props` member has type arguments, such as Mantine's `OverflowList` (`Factory<{ props: OverflowListProps<any>; … }>`), now gets those props. It used to get the payload's own keys (`props`, `ref`, `signature`, `stylesNames`, `vars`) as props. A payload is never used as the props type, and one whose `props` member isn't a named type is reported as a skipped candidate.
- - **Function types keep every parameter and their return type:** `(value: number) => ReactNode` used to print as `(value: number) => void`, a function with no parameters as `(e: void) => void`, and one with several parameters as opaque text. Parameter and return types are shown as written, names and generics included (`<T>(item: T) => ReactNode`), and a function inside a union or array is parenthesized (`string | ((theme: Theme) => CSSProperties)`).
  - **Handler types keep their names:** `onChange?: React.ChangeEventHandler<HTMLInputElement>` used to print as `(e: React.ChangeEventHandler) => void`.
  - **Breaking (canonical JSON and Rust API):** `PropType::EventHandler` (`kind: "eventHandler"`) is replaced by `PropType::Function` (`kind: "function"`, with `typeParams`, `params: [{ name, type }]` and `returnType`), and `OpaqueReason::MultiParamFunction` is removed. The parse cache schema moves to 15.
- - **A prop two intersection members declare has both types:** `A & B` used to keep whichever member declared a prop first, dropping the other declaration. As in TypeScript, the prop now has the intersection of both types (literal unions reduce to their common values, so `("default" | "destructive") & ("default" | "info")` is `"default"`), is required when either member requires it, and lists both declarations. An interface's own declaration still replaces the one it extends.
  - **In Full mode, a prop beside `ComponentProps<"div">` also has the element attribute's type:** recharts' `onTimeUpdate` next to a div's attributes is `ReactEventHandler<HTMLDivElement>` intersected with recharts' handler. Curated mode does not read React's declarations, so there the prop keeps the other member's type.
- - **A JSDoc comment documents only the declaration right after it:** a comment used to attach to whatever started within a few lines after it, so the first prop of `function Badge(props: { tone: string })` took the component's description, an inline object field took its prop's description or `@deprecated` tag, and a comment above a `const` or a license header could become a component's description. Only modifiers, keywords, decorators and other comments may now stand between a comment and what it documents, as in TypeScript.
- - **Opt-in loading of package types:** `--load-dependencies` (config `loadDependencies`, NAPI and Vite plugin `loadDependencies`, Rust `PipelineOptions::load_dependencies`) resolves the types your props import from installed packages, loading only the declarations those names reach instead of whole packages. With it on, shadcn's components gain 11,394 props and 349 fewer have none, and "Cannot resolve type" warnings drop from 378 to 55; chakra's drop from 323 to 25 and antd's from 112 to 58. A run stays 29–42× faster than react-docgen-typescript on the same projects. A type that still can't be found says why: its module didn't resolve, the package ships no types, or its types don't export it. Off by default; with it off, output is unchanged.
  - **Breaking (Rust API):** `LexedExport::LocalDeclaration` gains `declared_as`, the local name behind `export { Base as Name }`. The parse cache schema moves to 16.
- - **Namespace re-exports resolve:** a type reached through a namespace, such as `import { Menu as MenuPrimitive } from './ui'` and then `MenuPrimitive.RootProps`, now resolves when `./ui` re-exports the namespace (`export * as Menu from './menu'`, or `import * as menu from './menu'; export { menu as Menu }`) or declares it (`export namespace Menu`).
- - **Module resolution follows TypeScript more closely:** without a configured tsconfig, each file uses the nearest `tsconfig.json` (its `paths`, `baseUrl` and `extends`). The tsconfig's `customConditions` apply, `.d.mts`/`.d.cts` declarations resolve, and an import written as `./button.js` finds `button.ts`. On React Spectrum, unresolved types drop from 586 to 180; on shadcn, unresolved imports from 205 to 16.
  - **Package declarations:** a package whose `exports` list `"import"` before `"types"` now resolves to its declarations, and a declaration path that doesn't exist (an unbuilt workspace package) is reported as unresolved instead of silently resolving to a missing file.
  - **Breaking (Rust API):** `resolve_package_dts_path` takes the `PipelineOptions`.
- - **Components that inherit one interface share its resolved props instead of copying them,** and the interface is resolved once per run for every component whose context would resolve it the same way. Output is unchanged; on large design systems extraction is up to 40% faster and peak memory up to 45% lower.
  - **`ComponentEntry::props` and `notable_inherited` hold `Arc<ParsedProp>`** (Rust API only). Read a prop as before; change one through `Arc::make_mut`, which copies it first when another component shares it, so the change stays with that component.
- - **An alias over an indexed access that can't be evaluated keeps its name:** with `--load-dependencies`, `z.infer<typeof schema>` printed as `typeof schema["_output"]`. Like an alias over a conditional or mapped type, it now shows as `z.infer<typeof schema>`, and project aliases such as `type Side = (typeof SIDE_OPTIONS)[number]` show as `Side` instead of their source. An indexed access on a declared type passed as an argument (`z.infer<Parsed>`) now evaluates.
  - **`typeof X` keeps its `typeof`:** a value's type that can't be evaluated printed as the bare value name (`ReturnType<useTree>`, `JSON.parse`); it now prints as `ReturnType<typeof useTree>` and `typeof JSON.parse`, as TypeScript does.
- - **`injectDocgenInfo`:** assigns each component its react-docgen-typescript docs as `__docgenInfo`, for Storybook 10 and Storybook 11 with `features.docgenServer: false`. A change re-transforms every module whose components it changed, so Storybook's controls follow edits through HMR. Set `typescript.reactDocgen: false` so Storybook's own docgen plugin doesn't overwrite them.
- - **Watch mode follows configuration changes:** editing a tsconfig, jsconfig, `package.json` or lockfile in or above a source directory (installing a package, changing `paths`) now re-extracts everything and reports every component that changed, instead of needing a restart. `caliper-docgen watch` and the Vite plugin (dev server and `vite build --watch`) watch those files.
  - **New API:** `WatchSession::is_resolution_config` and `WatchSession::resolution_config_files` in core, and `isResolutionConfig(sessionId, file)` and `resolutionConfigFiles(sessionId)` in the NAPI binding. `update_file` / `extractFileIncremental` on such a file returns the full delta.

## 0.3.0

- - **A parse cache written by any other build is discarded.** The cache file now starts with the schema version, the crate version and a fingerprint of the code that produces it; any mismatch rebuilds the cache. Before, extractor changes that kept the cached data's shape served stale `.d.ts` results until someone remembered to bump a version, and two tool versions sharing a cache directory could read each other's data.
  - A cache from this build that cannot be decoded is reported with an `Info` diagnostic, then rebuilt.
  - **`stats.dtsFilesParsed` and `stats.dtsCacheHits` count every `.d.ts` file the run used,** including TypeScript's own lib files. Before, they counted only `.d.ts` files inside the source directories, so they usually read 0.
  - The cache file is now `dts.msgpack`; an old `dts-v1.msgpack` is ignored and can be deleted.
- - **Default exports:** anonymous default-exported components are detected and named after their file: `export default (props: P) => …`, `export default memo(function Badge(…))`, `export default forwardRef<El, P>(…)` and `export default class extends Component<P>`.
  - **Wrapper types:** `Required<P>` as a props type marks P's props required, and `PropsWithChildren<P>` adds a `children` prop.
  - **Excludes:** the built-in `.test.`, `.spec.`, `.stories.`, `__snapshots__` and `node_modules` checks, and user excludes, now apply to the path inside each source directory. Before, a project checked out under a directory such as `my.test.repo` produced no components and no warning.
- - **Applying every watch update in order now reproduces the snapshot exactly.**
    - `updatedKeys` includes components whose key moved because a same-named component elsewhere appeared or disappeared. Before, a client applying updates kept a stale entry under the moved key.
    - **Breaking:** `IncrementalUpdate.diagnostics` now holds only the diagnostics a change added; the new `removedDiagnostics` lists the ones it removed. Before, it re-sent the changed file's current diagnostics, and fixed diagnostics never left a client's list.
  - **The Vite plugin applies and announces changes one at a time,** so `caliper-docgen:update` events arrive in revision order across files. `CaliperDocgenUpdate` gains `removedDiagnostics`.
- - **Each component reports how it was recognized:** `detectedBy` is one of `functionDeclaration`, `forwardRef`, `fcAnnotation`, `hocWrapper`, `classComponent`, `forwardRefExoticDecl`, `anonymousDefaultExport`, `attachedSubComponent`, `typedFunctionExpression` or `wrapperTypeArgument`. The last two are inferred from a function's shape and what it returns; the rest are explicit declaration forms. It is in the JSON output, the JSON schema and the TypeScript types.
  - **Breaking (Rust API):** `ComponentEntry` gains a public `detected_by` field, and `DetectionRule` serializes in camelCase. The parse cache schema moves to 14.
- Component detection now needs evidence that something renders, so typed helpers, selectors, contexts and stores no longer appear as components:
  
  - **Functions:** a PascalCase function with a typed props parameter must contain JSX or an element factory call, call a hook, return `null`, `children` or a component call, or declare an element return type. That covers arrows, function expressions, functions wrapped in a call, and function declarations. `FormatName = (u: User) => string`, `debounce((q: Row) => …)` and generators are now declined with a `SKIPPED_CANDIDATE` note that says why.
  - **Generic wrapper calls** (`factory<F>(…)`, `withContext<El, P>("div")`): the first argument must be a function that renders, a component reference, a wrapped component, or a tag name next to an element type or factory payload. `createContext`, `createStore`, `makeLabel<P>("button")` and similar are declined.
  - **`.d.ts` declarations:** `declare function Button(props: P): JSX.Element` is now detected.
  - **Async server components** are detected.
  - **Aliases:** `memo(Card)` no longer hides an exported `Card`. A call that doesn't look like a component wrapper (`getDisplayName(Card)`) is no longer a component.
  - **Unresolvable props:** a wrapper component whose props live in an uninstalled package is kept instead of dropped. This restores 81 Chakra components.
- Two files that export an enum with the same name now give the same output on every run: the first file path in sorted order wins, and a `DUPLICATE_ENUM_NAME` warning names both files. Before, hash order picked the winner and nothing was reported. Enum keys on Windows paths are also split correctly. The on-disk parse cache is rebuilt once (schema 5).
- - **Each diagnostic is reported once.** Identical diagnostics from many components merge into one, with a new `affects` field listing those components' output keys. Mantine's output drops from 24,009 diagnostics to 563 and from 24 MB to 15.6 MB; chakra-ui drops from 4,538 to 583 diagnostics.
  - **Diagnostics are sorted** by file, line, column and message, with errors before warnings at the same spot.
  - **`IncrementalUpdate.diagnostics`** holds the changed file's diagnostics plus those of every re-resolved component.
  - **CLI:** the `×N` counts still count affected components.
  - **Help text:** indexed-access and template-literal diagnostics no longer tell users to "enable typescript-go", which is not an option.
  - **Breaking (Rust API):** `Diagnostic` has a new public `affects` field, so struct literals need it; `Diagnostic::new` is unaffected. `Diagnostic`, `DiagnosticSeverity` and `DiagnosticCode` now implement `Eq` and `Hash`.
- An interface that extends a type imported through a barrel file (`import type { UnstyledProp } from "../styled-system"` where `index.ts` re-exports it) now picks up that type's props. Before, the barrel was treated as the declaring file, so the props were dropped with an `UNRESOLVABLE_IMPORT` warning. On the Mantine and Chakra sources this raises the share of react-docgen-typescript's own props that Caliper reports from 13% and 18% to 86% and 85%.
- - **A generic type alias used as a prop's type takes its arguments.** `size: StyleProp<MantineSize>` now resolves to `MantineSize | MantineSize[]`. Before, it resolved to the alias's own parameter name (`Value | Value[]`), as though `Value` were a type.
  - Leaked parameter names in prop types drop from 25,624 to 72 on Mantine, 721 to 111 on react-spectrum, and 23 to 4 on chakra-ui. What remains is mostly generic components' own type parameters, which react-docgen-typescript also leaves unresolved.
  - Mantine's `classNames` keys become the real selector names, and MUI's `sx` callbacks name `Theme`.
- Two props-resolution gaps are closed. A generic interface now receives its type arguments: `Box<string>` for `interface Box<T> { value: T }` yields `value: string`, including through the interface's own `extends Box<T[]>`; before, `value` stayed the unresolved placeholder `T`. And a barrel file written as `import type { X } from "./x"; export type { X };` is now followed like `export type { X } from "./x"`; before, anything imported through such a barrel failed to resolve. On the Mantine source this raises the share of react-docgen-typescript's own props that Caliper reports from 87% to 92%.
- - **Breaking (canonical JSON):** each distinct prop is written once, in a top-level `props` table, and a component's `props` and `notableInherited` map each prop name to an id (16 hex digits). Read a prop as `output.props[output.components[key].props[name]]`. The same prop has the same id in every output and update of a build. Mantine's output drops from 19.3 MB to 3.6 MB and parses 7× faster. This covers `extract --json`, `--format canonical`, the NAPI functions and the Vite plugin's virtual module; `--format rdt` and `--format storybook` keep props inline.
  - **Breaking (watch updates):** an update carries `props` with every prop its `updatedComponents` refer to. Merge it into the output's table; ids no component refers to can be dropped. The Vite plugin's `caliper-docgen:update` event carries it too.
- - **Faster extraction on large projects:** resolved components move into the output instead of being copied, the canonical JSON is written in parallel, and the CLI uses mimalloc. Mantine extracts in 41 ms instead of 83 ms and Spectrum in 47 ms instead of 63 ms, with identical output.
  - **Fix:** `--out` to a device or FIFO such as `/dev/null` failed with a permission error, because the atomic write staged its temp file in `/dev`. Such targets are now written in place.
- Package metadata and license. The crates and npm packages now carry repository, homepage, documentation and keyword fields and a README, so crates.io, docs.rs and npmjs.com link back to the project. Starting with this release the license is FSL-1.1-MIT (each version becomes MIT two years after its release); 0.2.1 and earlier stay AGPL-3.0-or-later.
- Components wrapped in parentheses or a trailing `!`, such as `export const Button = (forwardRef<El, Props>(...))`, are now detected. They were silently skipped before.
- `Pick` and `Omit` now understand any key expression TypeScript code commonly uses: string literals and unions of them, a key alias (`type Keys = "a" | "b"`), `keyof Other`, `Exclude<…>` and `Extract<…>`, a mix such as `"a" | More`, and keys passed through a generic parameter. Before, an alias key set picked nothing or omitted nothing, silently. When the keys can't be known statically, a warning says so. The base can also be any type now, including an intersection such as `Omit<A & B, "k">`. In `caliper-docgen-core`, `CollectedTypeAlias::Pick` and `::Omit` carry a structured `keys` type instead of key lists. The on-disk parse cache is rebuilt once (schema 12).
- Removed eight options that were accepted but never used: `reactVersion`, `crossPackage`, `pandacssOutdir`, `variantFunctions`, `vanillaExtract`, `resolveComplexTypes`, `extraPaths` and `knownTypeOverrides`. This also removes the CLI flags `--react-version` and `--no-cross-package`, and the `reactVersion` option of the Vite plugin. A `docgen.config.ts` that still names one now fails with an error naming the field, instead of looking honored. Extraction output is unchanged.
- An unreadable `@types/react` or TypeScript lib file now raises an `IO_ERROR` diagnostic instead of being parsed as an empty file and cached that way. `--format rdt` and `--format storybook` now exit with an error if serialization fails instead of printing nothing.
- - **Cold extraction is 19–35% faster** with identical output. On the calibration corpora: react-spectrum 150 → 97 ms, Mantine 180 → 146 ms, shadcn 68 → 51 ms, chakra-ui 33 → 25 ms, Ant Design 44 → 34 ms.
    - Each import specifier is resolved once per directory instead of once per component.
    - Hot lookups key on the path string instead of hashing a path component by component.
    - Discovery walks in parallel and only canonicalizes symlinks.
  - An import that resolves to a non-UTF-8 path now reports an `UNRESOLVABLE_IMPORT` diagnostic instead of being dropped silently.
- - **A function counts as a component only if it returns an element.** Its own `return`s, or its arrow body, must hold JSX or an element factory call. That includes through conditionals, `&&`, arrays and calls such as `items.map(i => <li/>)` or `createPortal(...)`, and a local initialized with JSX and then returned.
    - Returning `null`, `children` or a component call also counts, as does calling a hook.
    - JSX that is built but never returned, JSX only inside a nested callback, or JSX inside a returned object no longer counts. A typed helper that builds a label and returns a string is no longer a component.
  - **An element return type must be React's:** `ReactNode`, `ReactElement` or `JSX.Element` imported from React, or not imported at all. The same name imported from another module no longer makes a function a component.
  - Across the five calibration corpora this drops one component, antd's `QRcodeStatus`. It returns the result of a render function chosen at runtime, which only its type shows to be an element.
- - **`tsconfigPath` is read the way TypeScript reads it:** block and line comments, `extends`, `baseUrl` and `paths` wildcards. Before, a hand-written reader understood only line comments and ignored `extends`. Any config it could not parse silently produced no aliases, so every aliased import failed to resolve with nothing pointing at the config.
  - **A tsconfig that cannot be read or parsed is reported once,** as a warning naming the file.
  - **React Aria's `RenderProps<T>`** gives `className`, `style` and `children` as a value or a function of the render state. Before, `className` and `style` lost their function form and `children` was dropped.
  - **A parse-cache file over 256 MB is reported and ignored** rather than read into memory.
- `SKIPPED_CANDIDATE` diagnostics now report the line and column of the declaration they skipped. Before, both were empty.
- Two diagnostic codes that were overloaded now have their own. A type that references itself reports `CIRCULAR_REFERENCE` instead of `MAX_DEPTH_EXCEEDED`, which now means only that nesting was too deep. A missing `@types/react` or TypeScript lib file reports `MISSING_TYPE_LIBRARY` instead of `UNRESOLVABLE_IMPORT`. Filters on the old codes need updating. The on-disk parse cache is rebuilt once (schema 6).
- - **Writing the output is faster, with byte-identical JSON.** Mantine's full run drops from 137 to 90 ms; react-spectrum's from 93 to 71 ms. Prop types are now streamed to the serializer instead of being built as an intermediate JSON tree first.
  - The JSON key order of prop types is now fixed by the code. Before, it depended on whether a dependency enabled a `serde_json` feature.
- Type arguments are now carried as structured types instead of display text. Several props that were silently wrong now resolve correctly:
  
  - `Pick<Base, "T">` inside a generic interface keeps the key `"T"`.
  - A type named `Infinity` or `NaN` is that type.
  - Function-typed arguments resolve instead of becoming opaque.
  - `extends Required<T>` keeps `T`'s props and marks them required.
  - `extends ComponentPropsWithoutRef<typeof Button>` yields `Button`'s props instead of HTML attributes for an element called "typeof button".
  - Nested object arguments no longer raise a false circular-reference note.
  
  In `caliper-docgen-core`, `ComponentMapping::props_type_args` and `ExtendsRef`'s `type_args` are now `Vec<CollectedType>`. The on-disk parse cache is rebuilt once (schema 11).
- - **A project's own type named like a builtin is that type.** A local or imported `ReactNode`, `CSSProperties`, `Ref`, `Partial` or `Required` now resolves as declared. Before, these were matched by spelling first and read as React's or TypeScript's type, or as an empty utility. Mantine's own `CSSProperties`, which extends React's with an index signature, now appears as itself in `style` props.
  - **React meanings need React's binding; TypeScript utilities need no binding at all.** `PropsWithChildren` and `PropsWithRef` count as React's.
  - **When a builtin name is bound to something that can't be resolved,** such as a package that isn't installed, React's meaning is still used, and an `Info` `UNRESOLVABLE_IMPORT` diagnostic says so. react-spectrum's source-only mirror reports 29 of these, for types from `@react-types/shared`. Before, they were silent.
- Components written as a plain typed arrow or function expression, such as `export const Button = ({ variant }: ButtonProps) => ...`, are now detected. Async and generator functions and functions whose first parameter is not a named type are ignored. On the Ant Design source this raises component recall against react-docgen-typescript from 88% to 96%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 8).
- `Pick` and `Omit` now work when their first argument is itself generic (`Pick<Gen<number>, "x">`) and when `Omit` removes `keyof Other`. Before, a generic first argument dropped the props with no warning, and `keyof` omitted nothing. Known HTML attribute interfaces named inside these utilities no longer raise an unresolvable-type warning.
- - **The virtual module reloads on every change** with the session's current output: renamed or deleted components disappear, disambiguated components keep their own keys, and enums and diagnostics stay current. Before, it was never invalidated after the first load, entries were keyed by display name, and removals were never applied.
  - **`caliper-docgen:update` carries `revision`, `updatedKeys` and `removedKeys`.** A change that produced no new revision (an excluded story, for example) sends nothing. A change that could not be applied is logged and sends nothing; before, an empty update was sent.
  - **`vite build --watch` stays current.** Every source directory is watched, so a change to a file no bundle module imports still rebuilds, and each change is applied before the rebuild loads the virtual module. Before, rebuilds served the first build's output.
  - **A build fails when extraction fails,** instead of shipping an empty virtual module.
  - The `CaliperDocgenUpdate` type is exported.
- Watch mode now agrees with a fresh extraction. The session snapshot lists enums under their public names (it exposed internal `path:name` keys), an import added by an edit is followed by later edits (the dependency graph was only built once), and a wrapper-call guess that resolves to no props is omitted the same way. The unused public `WatchSession::source_cache` field is removed.
- - **Watch output equals a cold extract.** After any edit, creation, rename or deletion, a watch session's snapshot has the same components, enums and diagnostics as `extract` over the same files. Before, edits to a dependency reached through a barrel or a `../` import were missed, deleted files' components stayed until restart, excluded files such as stories added components, a disambiguated component's edit could land under another component's key, and the first run's diagnostics were dropped from later snapshots.
  - **Precise re-resolution.** Each component records the files, project-wide names and module resolutions its props depended on; a change re-resolves exactly the components it can affect.
  - **`IncrementalUpdate` gains `revision`, `updatedKeys` and `removedKeys`,** so a consumer can apply an update to a keyed map and drop removed entries.
  - **Breaking (Rust API):** `WatchSession`'s fields other than `options` and the `ReverseDeps` type are removed; `WatchSession::rebuild()` is new. A deleted file is now a removal, not an `IoError`.
  - Resolve diagnostics are ordered by file and source position.
- Components built by a wrapper call whose props travel as a type argument are now detected, for example `const Button = polymorphicFactory<ButtonFactory>(...)` where `ButtonFactory` is `Factory<{ props: ButtonProps }>`, or `const Item = withContext<HTMLDivElement, ItemProps>("div")`. Detection is by shape, not by library name: a PascalCase binding initialized with a generic call whose first argument is a function, a tag name or a reference, with the props type picked from the type arguments. Element and ref types are skipped, and a guess whose props resolve to nothing is reported as a `SKIPPED_CANDIDATE` note instead of being listed. On the Mantine source this raises component recall against react-docgen-typescript from 29% to 82%. More components can appear in output than before. The on-disk parse cache is rebuilt once (schema 9).

## 0.2.0

  - `caliper-docgen` CLI with `--format canonical | rdt | toon`, `docgen.config.ts` loading, watch mode, and a `schema` subcommand that exports the component metadata as a Draft-07 JSON Schema. `--format rdt` emits a `react-docgen-typescript`-compatible shape (see `MIGRATING.md`); `--format toon` is a token-optimized output for LLM agents.
  - Cross-package `.d.ts` resolution with an atomic, bounded on-disk cache, and a plugin system (`DocgenPlugin` / `PluginRegistry`) for AST and component resolution hooks.
  - NAPI binding and a Vite plugin that expose the canonical format.
  - An `lsp` subcommand scaffold with bounded framing and the initialize/shutdown/exit lifecycle. It does not serve prop hovers yet.
