# caliper-docgen-storybook

## 0.6.0

- - **The Storybook addon resolves a component when a story asks for it:** the session indexes where components live from parsing alone and resolves one on request (`lazy`, default `true`; `lazy: false` restores resolving every component at start). Chakra with dependencies answers its first story in 55–121 ms where the eager session took 357–425 ms, and peaks at 419 MB where the eager one peaked at 658 MB. Answers are identical to the eager session's.
  - **A background warm-up loads what stories share:** after a lazy session starts, it resolves a few components so dependency declarations are loaded before the first story asks (`warmUp: false` turns it off).
- - **The Storybook addon documents more by default:** it reads dependency types (`loadDependencies`, default `true`) and lists every inherited prop (`collapseInheritedProps`, default `'none'`), so library-typed props resolve and fewer components fall back to Storybook's own docgen. New options: `htmlAttributes` (`'curated'` | `'full'` | `'none'`), `loadDependencies`, `collapseInheritedProps`.
  - **Fallbacks are visible:** a component handed to Storybook's docgen is logged once as a warning with the diagnostics that caused it.
  - **Edits to a tsconfig, `package.json` or lockfile reach the addon** like a source edit, instead of being missed until restart.
  - **The Vite plugin logs extraction diagnostics** once each (`logLevel`, `onDiagnostic`) and takes `htmlAttributes`.
  - **Windows paths work in the Vite plugin:** `C:\` source directories and backslash file paths are recognised.
- - **A union a dependency declares as a tuple is expanded:** `type Align = (typeof ALIGN_OPTIONS)[number]` over `declare const ALIGN_OPTIONS: readonly ["start", "center", "end"]` is `"start" | "center" | "end"`, read from the file that wrote it, as TypeScript reads `typeof X`. Radix declares `Align` and `Side` this way, so shadcn's Radix-based popover, tooltip, hover card, dropdown menu and select now show their `align` and `side` literals instead of the bare names.
  - **A type that comes from a call says so:** the help of "typeof 'X' could not statically evaluate" names the cause (a value built by a call, such as a zod schema behind `z.infer`) and the remedies.
- - **A spread in an `as const` array adds the values of the array it names:** `['default', 'primary', 'danger', ...PresetColors] as const` was read as its three literals, so antd's `Button` and `PickerButton` `color` lacked the preset colors. A spread of something that is not an array in the project leaves its values out and warns. The parse cache schema moves to 23.
  - **`import React from "react"` names React's types as `import * as React` does:** antd's spelling left `React.CSSProperties["flex"]` and `React.HTMLAttributeAnchorTarget` unresolved. `Flex`'s `flex`, `align`, `justify`, `gap` and `wrap` are now csstype's unions, and `FloatButton`'s `target` is its four anchor targets.
- - **More defaults are the components':**
    - `const { dot = false, overflowCount = 99 } = props` in the body documents those defaults, as a destructured parameter does (antd's `Badge`, `Sider`, `Modal`, `Progress`). A renamed one (`tone: t = 'a'`) is the prop `tone`, not the local `t`, in both places.
    - The same default applies to a field of an inline object type in the props (`props: IconProps & { size?: 'S' | 'M' }`, Spectrum's illustrations).
    - A mapped type keeps the JSDoc tags of the member it maps, so a recipe's `/** @default "md" */` becomes the prop's default (Chakra's `size`, `variant`, `shape`).
- - **A property of a named type's props resolves when its declaration can't be read:** `RcTooltipProps["visible"]` with `type RcTooltipProps = React.ComponentPropsWithoutRef<typeof Tooltip>` is `Tooltip`'s `visible` (antd: `Tooltip.open` and `defaultOpen` are `boolean`; Chakra: `Flex.align`, `Grid.templateColumns` and 54 more style props; shadcn: `Calendar.buttonVariant` and 144 more). The read takes the props the type would have in an `extends` clause and picks the property out, as TypeScript does for an indexed access. An access that finds nothing is reported as before, and a type that reads itself stays opaque.
  - **The oracle agrees:** against TypeScript 7.1's checker, props Caliper contradicts fall to 0.00% on every corpus (Mantine was 0.34%, antd 0.25%).
- - **Members of an intersection that reach the same type each keep their props:** `Pick<Partial<T>, K> & Omit<T, K>` (Ark UI's `Optional`) lost its second member as a "circular reference", because the members shared one cycle set. Chakra's Ark-based components (`AccordionRoot`, `SliderRoot`, `ListboxRoot`, `TreeViewRoot`, …) gain 676 props with `--load-dependencies`, 36 false `CIRCULAR_REFERENCE` diagnostics go away, and where an Ark prop overrides a style prop (`CarouselRoot.padding`, `page`) it takes Ark's type, as `Assign<A, B>` does in TypeScript.
  - **A destructuring default is the component's default for that prop wherever its type is declared:** `function AlertDialogCancel({ variant = "outline" }: Pick<ComponentProps<typeof Button>, "variant">)` now has `variant: "outline"`; before, only props from an interface or object alias the component names got one (shadcn: 175 defaults).
- - **Names that were reported unresolvable and are not:** each is now the type it names, without a warning, which keeps the component out of the Storybook addon's fallback.
    - A type React declares that no builtin list names (`UIEventHandler`, `Key`, `AriaRole`, `ReactDOMAttributes` imported from `DOMAttributes`), read from React's own declarations.
    - A generic component's own type parameters (`function ActionBar<T extends object>(props: ActionBarProps<T>)`), registered as the placeholders they are.
    - A class used as a type (`value: CalendarDate`), recorded as a declaration with no members.
    - ES2015 globals: `Iterable`, `Set`, `Map` and `Promise`, read from TypeScript's `lib.es2015.*` files when installed.
  - Components with a warning, with `--load-dependencies`: Spectrum 29% → 0.4%, antd 27% → 9%.
  - The parse cache schema moves to 22 (component mappings record their type parameters).
- - **Chakra with `--load-dependencies` resolves instead of giving up:** the share of its components with a warning drops from 92% to 3%. Three causes, all fixed:
    - A type declared inside `namespace X {}` that names a sibling (csstype's `DataType.Color = ColorBase | ...`) now finds it. Its members were lost before, in project sources as well as dependencies.
    - `T extends unknown ? Omit<T, K> : never`, the idiom that distributes over a union, takes its true branch, so a props base written that way is no longer opaque.
    - The nesting limit counts one type expression. An alias body starts again at 0, and the declarations a reference passes through are bounded by the names in progress, so a prop 15 levels down no longer runs out of depth inside four csstype aliases.
  - The parse cache schema is unchanged.
- - **Turn the on-disk caches off:** `--no-cache`, `cache: false` in `docgen.config.ts`, the `cache: false` option of the native binding, the Vite plugin and the Storybook addon. A run with the cache off reads nothing from and writes nothing to the cache directory (neither the declaration parse cache nor the dependency index) and parses everything; the output is the same.
  - **Breaking for Rust embedders:** `PipelineOptions` has a new public field, `use_cache` (default `true`). A struct literal that names every field needs it; one that ends in `..Default::default()` does not.
- - **The default cache directory belongs to the project, not the working directory:** with no `cacheDir`, the caches live in `node_modules/.cache/caliper-docgen` under the nearest ancestor of the first source directory that has a `node_modules` or a `package.json`. Running from another directory no longer misses the project's cache or creates a `node_modules` there, and the CLI, the Vite plugin and the Storybook addon share one cache. A source directory in no project uses a directory in the OS temp directory.
  - **A run that learned nothing new no longer rewrites the dependency index:** the project's own imports are resolved every run and never reach the index, yet they made every run write it again (shadcn with dependencies, warm: 97.7 → 93.0 ms; Chakra: 285.7 → 259.9 ms).
- - **Breaking: the canonical JSON writes repeated lists once (`schemaVersion` 2).** A component's `props` is now an array of prop set ids into a `propSets` table (prop name to prop id), and an inheritance layer's `omitted` and a diagnostic's `affects` are ids into a `nameLists` table. Chakra with dependencies: 32.1 MB to 4.3 MB, `JSON.parse` 103 ms to 12 ms, and the Storybook addon's session index 6.9 MB to 1.8 MB. Readers resolve the ids; the Vite plugin and the Storybook addon already do, and `--format rdt` and `--format toon` are unchanged. See ADR 0018.
- - **Radix and Base UI components resolve with `--load-dependencies`:** shadcn's components with a warning drop from 32% to 10%.
    - `typeof Primitive.div` (Radix's `declare const Primitive: Primitives`, a mapped type over `(typeof NODES)[number]` whose values extend `ForwardRefExoticComponent<PrimitivePropsWithRef<E>>`) has the props of that component with `E` bound to `"div"`. A `declare const` records its declared type as the alias `typeof X`, and the loader takes it with the value.
    - Base UI's `{ [K in keyof ComponentPropsWithRef<"div">]: Wrap<…[K]> }` props base is the element's attribute layer, as `ComponentProps<"div">` is; the wrapper on each value is not applied (an information diagnostic says so).
  - **A default export that is an import resolves through it:** `import Tooltip from './Tooltip'; export default Tooltip` is a re-export of `Tooltip`'s default, so antd's `ComponentProps<typeof RcTooltip>` finds `@rc-component/tooltip`'s component (antd: 9% → 5% of components with a warning).
- - **A recursive generic alias is a cycle, not a depth overrun:** `type CssVars<V = CssVariable> = ... | CssVars<V>[]` pinned its argument to a file again at every level, so the recursion never repeated a type and ran 20 levels deep to a warning. It now stops at the second level, as information. Mantine: components with a warning drop from 69% to 3% (every component with a `vars` prop).
- - **The canonical JSON names its version:** `ExtractionOutput`, `IncrementalUpdate` and the session index carry `schemaVersion` (1, the shape with the props table). The Vite plugin, the Storybook addon and `ExtractionOutput`'s `Deserialize` reject a version they don't read, with an error that says what to update. `--format rdt` and `--format toon` are unchanged. See ADR 0017.
- - **Faster on large style systems:** a named type, and an HTML element's attribute declaration, are resolved once per run and shared by every component that reaches them, as interface chains already were. A thread that needs a type another is resolving waits for it instead of resolving it too. Chakra with `--load-dependencies`: resolution CPU 3.56 s → 2.80 s (main: 2.75 s), peak RSS 395 → 350 MB (main: 372 MB).
- - **A story's component is found when its file holds several:** `import Card from './Card'` now reaches the component the module exports as `default`, `export { Inner as Card }` reaches `Inner`, and a default import falls back to the name the story gave it. On ant design 83 sampled stories, the addon answers 77 where it answered 58 (no story finds "no component in session" any more; five stay with Storybook for incomplete props).
  - **`component: Select.Option` works with a named import:** Storybook's resolver reads a member only of `import * as`; the addon now finds the `Select.Option` component.
  - **A story the session can't match says why:** the debug log lists the components the file does have.
- - **The Storybook addon answers a story up to 3.5× faster on large projects:** it no longer sweeps every source file from JavaScript on each request. The native session checks the files, in parallel, once per story (Spectrum's 129 real stories: 2.2 s → 0.6 s, 15 ms → 4 ms per story).
  - **Session start no longer serializes every prop:** the new `initializeSessionIndex` returns only each component's file, name and the diagnostics. Chakra with dependencies skips a 25 MB JSON round trip.
  - **The native binding uses mimalloc:** session start is 15–30% faster, and Chakra with dependencies peaks 9% lower (small projects peak 20–30 MB higher).
- - **A component whose props are a union of object types has the props of every branch:** `(A & { multiple?: false }) | (B & { multiple: true })` (antd's `CascaderPanel`, shadcn's `SidebarMenuButton` and `TraceCollapsible`) kept only the first branch's type for each prop. A prop the branches type differently is now the union of those types (`multiple?: false | true`), and one that some branch lacks or marks optional is optional (`href`, `onOpenChange`).
- - **cva's `VariantProps` keeps its variants beside other props with `--load-dependencies`:** `React.ComponentProps<"button"> & VariantProps<typeof buttonVariants>` lost `variant` and `size` once the package was loaded, because the loaded declaration needs inference and the shortcut that covers it only stood in when the type was the whole props type. It now stands in for a member of an intersection too (shadcn: 84 components).
- - **`VariantProps<typeof x>` reads the variants of the `x` its own file declares:** two files that each declare an `itemVariants` (shadcn keeps a copy of every component per registry) no longer share the first one's by path, so a component listing `"xs"` for a size its own `cva` does not have is fixed. The declaration the file imports comes next, then the bare name.
- - **A wrapper call that names its props type keeps those props when it also receives a component:** `withContext<HTMLDivElement, OverlayProps>(BaseOverlay, "overlay")` has the props of `OverlayProps`, not only those of `BaseOverlay`. Chakra's `CodeBlockOverlay` goes from 1 prop to 843 and six other code-block components gain their style and HTML props.

## 0.5.0

- **Curated mode also gives a prop beside `ComponentProps<"div">` the element attribute's type:** recharts' `onTimeUpdate` next to a div's attributes is now `ReactEventHandler<HTMLDivElement>` intersected with recharts' handler in the default curated mode too, not only in Full mode. Curated mode reads React's declarations for this lookup only (ADR 0013), so nothing else in its output changes.
- - **A library's own declaration wins over a built-in shortcut:** with `--load-dependencies`, a component typed with `HTMLChakraProps<"div">` or Chakra's `ButtonProps` gets the library's real props (139 and 146 of react-docgen-typescript's, against 1 and 0 before), and Mantine's `StylesApiProps` its 8. Shortcuts remain only as fallbacks: when the package isn't loaded, or when its declaration needs a type checker (cva's `VariantProps`).
  - **Fewer library shortcuts:** `SxProps`, `SystemStyleObject`, `SystemCssProperties`, `OverridableStringUnion`, `ThemingProps` and `StylesApiProps` are no longer special-cased. Without their package loaded they stay named references with an `UNRESOLVABLE_IMPORT` warning, like any other uninstalled type; `sxProps` is no longer emitted as a type kind.
  - **Generic call props:** a component built by a generic factory takes its props from the factory's result type when that resolves, and an `export *` barrel reaches any exported value. A prop two members declare intersects, and `any` absorbs the intersection.
- - **`Exclude`, `Extract` and `NonNullable` evaluate over literal types:** `Exclude<"small" | "medium" | "large", "large"> | "default"` is the union `"small" | "medium" | "default"` (an enum in the RDT format, so a select control), as TypeScript evaluates it. They used to print as written.
  - **Template literals with number or boolean parts expand:** `` `h${1 | 2 | 3}` `` is `"h1" | "h2" | "h3"`, also inside an alias's arguments.
  - **A conditional decided by a member read evaluates:** `Payload["variant"] extends string ? … : string` takes its branch when the member's type is known, including when the payload declares no such member (Mantine's `variant` props now print their variants or `string` instead of the conditional's source).
  - **Member reads inside an alias's arguments evaluate,** through mapped types such as csstype's `Fallback<T>`: Chakra's style props print csstype's property types (`ConditionalValue<Property.Filter | … | AnyString>`) instead of `CssProperties["filter"]`.
- - **Props through conditional, indexed and mapped types:** a props type built as `T extends keyof Recipes ? Recipes[T]["__type"] : …` with a known `T`, or as a mapped type over a known type's keys (`{ [K in keyof Variant]?: … }`), now lists its props instead of a warning. Chakra's recipe props (`size`, `variant`, …) now appear: 332 of the 363 react-docgen-typescript reports on Chakra with dependencies loaded, none before.
  - **An alias argument that reads a member prints as what it reads:** `ConditionalValue<ButtonVariant["size"]>` prints `ConditionalValue<"sm" | "md" | "lg" | undefined>`, as TypeScript does.
- - **Components declared inside a function body are not documented:** a factory's returned component (`function createLeaf() { const Result = forwardRef(…); return Result; }`) or a local helper exists per call, and no module imports it by that name. Each is now an Info `SKIPPED_CANDIDATE` diagnostic instead of a component; React Spectrum's two `Result` entries and antd's local `PurePanel`, which shadowed the module-level one, are gone.
  - **Fewer skip diagnostics:** a PascalCase local that matches no component pattern (`const Comp = asChild ? Slot : "button"`) is no longer reported.
- - **A re-exported member of an imported component is documented with `--load-dependencies`:** `export const CheckboxHiddenInput = ArkCheckbox.HiddenInput` has the props of Ark's `HiddenInput` (Chakra: 11 components that react-docgen-typescript reports). Without the package loaded there is nothing to show, so it is left out. The parse cache schema moves to 21.
- - **Inherited React event handlers take their element:** with `--html-attributes full`, a component extending `React.SVGProps<SVGSVGElement>` or `ButtonHTMLAttributes<HTMLButtonElement>` listed `onClick` as `(event: MouseEvent<T>) => void`, with React's type parameter unbound. It is now `(event: MouseEvent<SVGSVGElement>) => void`, as TypeScript reads it.
- - **`Exclude`, `Extract` and `NonNullable` come from TypeScript's own definitions:** they were matched by name and evaluated only over literals. Now `type Exclude<T, U> = T extends U ? never : T` from the project's `lib.es5.d.ts` is evaluated the way TypeScript does, so a conditional alias over a bare type parameter distributes over the members of its argument, through aliases, `(typeof LIST)[number]` and `boolean`. A project's own `type Without<T, U> = T extends U ? never : T` works the same. `T & {}` removes `null` and `undefined`. Without TypeScript installed, these print as written, as before.
  - **A generic alias with a long expansion prints by name, as TypeScript and react-docgen-typescript do:** `Responsive<DimensionValue>` instead of its 80 literals three times over (React Spectrum: exact agreement with react-docgen-typescript's type text rises from 67.5% to 78.1%).
  - **A union drops `never` and a union of nothing is `never`.**
- - **`CSSProperties["key"]` reads csstype with `--load-dependencies`:** a prop typed `React.CSSProperties["pointerEvents"]` was always `string`, and `["zIndex"]` always `number`. With dependencies loaded, they now have csstype's types, as TypeScript does: `pointerEvents`, `objectFit` and `resize` are enums, `width` is `string | number` plus its keywords. Without dependencies, the previous answers stay.
  - **Indexed access reads the declaration first:** `Leaf["value"]` reads through `Leaf`'s ancestors in other files and binds their type arguments, and a member of a React type (`ButtonHTMLAttributes<HTMLButtonElement>["formAction"]`) reads React's declaration in curated mode. These used to print the access unevaluated or the unbound parameter.
  - **A literal-union alias inside a union contributes its members:** `Size | "xl"` is one union of literals, so the RDT format shows it as an enum, and a member it repeats is listed once. Printed text is unchanged; in `--json` the alias's members replace a nested `{"kind":"literalUnion"}`.
- - **Less memory with `--load-dependencies`:** a generic alias reference no longer resolves its arguments before expanding the alias (the expansion reads them again), and equal props built for different components are one allocation. Chakra's peak memory with dependencies loaded falls from 522 to 388 MiB. Output is unchanged.
- **String defaults keep their source quotes:** `({ size = 'md' })` gives the default `'md'`, not `"md"`, in every output format, as react-docgen-typescript and Storybook's React docgen print it. A double-quoted or template-literal default keeps its own quotes too.
- - **An omitted type argument takes its parameter's default:** `interface Props extends DOMAttributes` with `DOMAttributes<T = FocusableElement>` binds `T` to `FocusableElement`, as TypeScript does. Event handlers inherited from a library no longer print an unbound `MouseEvent<T>` (React Spectrum: 1,208 props), and `type Pair<A, B = A[]>` used as `Pair<string>` is `{ first: string; second: string[] }`.
  - **The parse cache schema moves to 20** (type parameter defaults are stored with each file's declarations), so existing caches are rebuilt once.
- - **A union lists each member once:** a union built from aliases that resolve to the same type prints that type once, as TypeScript does. React Spectrum's collection `children` printed `ReactNode | null | ReactNode | null | …` and now prints `ReactNode | null | (ReactNode | null)[] | …`; `T[] | readonly T[]` prints `T[]`.
  - **JSON unions are flat:** in `--json` output a union member that is an alias of a union now contributes that union's members in its place instead of a nested `{"kind":"union"}`. Printed type text is unchanged by this.
- **A wrapper-built component gets the props its factory's result type adds:** `const Button = factory<ButtonFactory>(…)` now also lists the props the type `factory` returns declares beyond the payload, such as Mantine's `component` and `renderRoot`, as react-docgen-typescript does. The factory may be reached through `export *` barrels, and editing it updates the components it builds in watch mode. On Mantine's core package, 360 missing props are now reported.

## 0.4.0

- - **New package `caliper-docgen-storybook`:** a Storybook 11 addon whose docgen provider answers argTypes from a caliper-docgen session. It resolves `meta.component` and `meta.subcomponents`, converts with `@storybook/react`'s own converter, applies saved edits before each answer, and hands a component it can't find, or one whose extraction reported a warning or error, to React's docgen. On a four-component example its first answer took 43 ms against React's 504 ms, and later answers 0.4 ms against 0.7–1.5 ms.
