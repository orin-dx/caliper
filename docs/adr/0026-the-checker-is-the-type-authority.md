# 0026. The checker is the type authority; oxc supplies syntax

**Status:** Accepted (2026-11-08) **Date:** 2026-11-07

## Context

ADR 0006 and 0007 made the TypeScript checker an opt-in second resolver, because a whole-project `tsc` run cost up to 9.3 s and 975 MiB (`docs/type-checker-integration.md`); ADR 0022 bounded it to a warm per-component request. The structural default still answers wrong without a marker: a type that is only a call signature becomes `{}`, `Omit`, `Pick` and `Partial` reached through an alias lose their effect, and a factory's props are taken from a name-matched interface (`docs/rdt-differences.md`, classes 4 to 6). A prototype found more: `[string, ...number[]]` prints as `[string, number[][]]` and a getter reads as a method. Each fix is another rule in a resolver that re-implements the type system.

tsrs (`oxc-project/tsrs`, Apache-2.0) is a Rust port of the TypeScript 7 checker at microsoft/TypeScript `3e9236361fa9`, the commit `typescript@7.1.0-beta` was built from. It speaks the same `--api` protocol: the 19 methods caliper calls are all present, and 87 one-prop fixtures got the same oracle verdicts as `typescript-beta`. A throwaway prototype through the Node client (not in the repository; these numbers are the record) measured on Chakra `ButtonProps` (1,138 props) a 43-47 ms snapshot and the first converted prop at 62-67 ms, where ADR 0022 measured 703 ms with `tsc` on a different program root (indicative, not an A/B), with tsrs peaking at 126-130 MiB. On 16 hand-written components the checker was equal or better on 14, worse on union member order and an unresolvable import. A polymorphic component instantiated through a virtual file gave 267 props for `'div'` where both engines give 2 today. tsrs's own benchmark (`bench/RESULTS.md`) reports 1.8 to 4.2 times TypeScript 7.1 beta's speed and 2.1 to 2.6 times less memory.

## Decision

The checker decides types and oxc decides syntax.

- **Authority.** The checker is the default source of a component's prop set, each prop's type, requiredness and description. oxc supplies candidate components (`extractor/evidence.rs`, `uses.rs`), defaults, JSDoc positions, source locations and declaration order, which is re-applied to union members because the checker sorts them by flags and value.
- **One projection model.** Checker facts convert once into the canonical model. Canonical JSON, TOON and the RDT view are projections of it, and no projection makes a type decision.
- **Fallback.** The structural resolver stays only for when the checker cannot answer: not installed or offline, an unsupported platform, a crash, a timeout. Its types carry `degradedBy` and the run carries one diagnostic.
- **Opt-out.** The checker runs unless `--no-checker` (`checker: false` in the config, the napi binding and the Storybook addon) turns it off; `--experimental-semantic-types` and `semanticTypes` are removed (S8).
- **Per surface.** The Storybook addon keeps ADR 0022: the structural answer first, the checker's within `semanticWaitMs`. Its premise that the checker is too slow for first paint was re-measured with tsrs in S4 and holds (Chakra's `Button`, 562 ms, 402 ms after the first-answer work). The CLI and agents wait for the checker, all candidates in one snapshot, with a timeout (10 s proposed).
- **Pin.** We pin exact tsrs crates (`tsrs_api` and `tsrs_vfs` `=0.24.0`, TypeScript `3e9236361fa9`) and bump them on purpose; the checker lane's `tsrs` binary (`0.23.0-ts7.1.0-beta`, the same TypeScript commit) follows them. A bump passes the deterministic construct suite (`apps/oracle/construct-suite`, being built on `feat/construct-suite`) and a tsrs-against-Go parity run of it. The weekly oracle keeps the Go `typescript` checker: an oracle running the checker that produced the answer agrees with it by construction.
- **Linked.** The product links the tsrs crates and asks `tsrs_api::Session` in process, on one thread with a 512 MiB stack, the stack the `tsrs` binary serves on; nothing is installed. `--tsc-path` (`tscPath`) runs a checker binary as a process instead, which is how the Go `typescript` beta stays the oracle and the parity gate. A checker process is replaced above an RSS threshold (`OnDemandConfig::max_rss_mib`) and after 64 programs. The linked checker is never replaced, since a fresh session raises this process's memory rather than returning it; past the same bound, read from its own arenas, it stops for the session and components keep their structural answer with a diagnostic. A panic closes its session and a fresh one answers the next request, and a file nested past 20,000 brackets is not given to it (trail 369 slice 2).
- **Collapsed React types.** `ReactElement`, `JSX.Element` and `ReactChild` stay collapsed to the `reactNode` terminal. No evaluation showed it hurting Storybook controls.

Linked rather than spawned (trail 369): the crates are published (0.24.0), the same recorded Chakra answer (3,776 requests) takes 141 ms in process against 367 ms over the pipe with equal answers, and there is no per-platform binary to ship or find. What it costs: a stack overflow inside the checker aborts the host process (the 512 MiB thread holds a type 10,000 deep and tsrs's 256 MiB parse threads one 200,000 deep; past 20,000 brackets a file is refused, but nesting written without brackets, such as a chain of 700,000 arrow types, is not bounded), a dropped session does not return its memory (trail 369 slice 2, done: it bounds the checker's arenas and then answers structurally, [gate measurements](../gate-measurements.md#in-process-guards-trail-369-slice-2)), and each linked artifact grows by about 22 MB.

## Consequences

- Supersedes "structural stays the default" in ADR 0006 and 0007 and 0007's "never a silent default" trigger. The rest of both stands.
- Deletable or shrinkable with a thin fallback, estimated from each file's header: in `crates/core/src/resolver`, `alias`, `chain`, `evaluate`, `substitute`, `named`, `primitives`, `extends`, `func`, `template`, `import`, `callee`, `memo`, `deps`, `collected` and `precedence` shrink to a no-generics subset and `mod.rs` by half; `dependency_types.rs` and `import_map.rs` go (the checker resolves modules; ADR 0010 and 0025 narrow to the fallback); in `extractor`, `interface` (but cva), `alias`, `values`, `reexports`, `asserted` and most of `visit` go, and `component`, `wrapper` and `mod.rs` shrink to candidate detection. About 7,600 of 25,300 non-test lines, 9,400 with no fallback, which Windows ARM64 rules out. `html`, `react`, `ambient`, `evidence`, `uses`, `defaults` and `jsdoc` stay; `crates/semantic` and `crates/tsc-client` grow and `convert.rs` is rewritten.
- Contract: `PropType` gains what the checker knows and it cannot hold: tuple element optional, rest and labels, `bigint`, `unique symbol`, enum identity, template literals, overload sets, call signatures on objects, a recursion marker, and a typed truncation in place of `Named` with checker text. React terminals (`ReactNode`, `CSSProperties`, `Ref`, `ElementType`, HTML attributes) are recognized by declaring path, as `is_react_declared` (`crates/semantic/src/component.rs`) does. `SCHEMA_VERSION` and `CACHE_SCHEMA_VERSION` bump (ADR 0017).
- No cache is keyed on a type id: ids are per checker and change with query order. Keys are file content, export name, instantiation and the tsrs pin. The checker does not see an edit it is not told about, so watch forwards every change. The whole-project `extract` keeps its answer on disk for the whole program only, keyed by every question its linked checker asked of the file system (failed lookups included) with a digest of each answer, the build's fingerprint (the pin with it) and the request; any different answer discards it whole (2026-11-12, `docs/type-checker-integration.md`).
- Unsolved: a per-component dependency closure from the checker (invalidation stays conservative), and the structural answer's gaps wherever the fallback runs.
- Risks: tsrs is pre-1.0, four releases in twelve days, and closed to pull requests (its README). Memory grew from 98 to 246 MB over 150 Chakra edits with each old snapshot disposed (#920 and #646 open). Determinism across checker counts is shown only on a 72-file program. There is no `@tsrs/win32-arm64` package, so those users get the fallback. The linked crates add about 22 MB to the CLI and to the napi binding.

Migration, each slice behind a deterministic gate, none on the oracle. The tsrs backend (the Rust client running on tsrs, PR 390) is done.

1. **S1** (done) Shared projection model and the new `PropType` variants, filled by the structural path where it knows them. Gate: a unit test per variant, golden JSON diff, cache schema test.
2. **S2** (done) Flag-based converter in `convert.rs`, memoized by type id within one snapshot, with a named-boundary policy and caps. Gate: the construct suite's expected JSON; reversed query order gives identical bytes.
3. **S3** (done) React terminals by declaring path. Gate: no regression against today's Chakra `Button` terminals.
4. **S4** (done, one gate failed) The checker's answer wins when it runs: the addon inside ADR 0022's window, the CLI waiting (`--semantic-timeout-ms`, 10 s), and a prop the checker could not read keeps its structural type with `degradedBy` (`docs/type-checker-integration.md`). Gate: checker-on output equals structural on the suite except a listed set of improvements (held by the checker lane); Chakra first answer at most 150 ms through the Rust client (measured 562 ms, then 402 ms once each answer was parsed once and a type's parts asked for once; FAIL: the floor of that request set with no round trips is about 230 ms, 81% of its bytes the property lists of Chakra's style-prop condition maps, so the seam has to change rather than the budget: [gate measurements](../gate-measurements.md#first-answer-s4), and ADR 0022's structural-first answer stands); the Storybook harness re-run (not run: it needs the corpora).
5. **S5** (done) Instantiation of generic and polymorphic components through a virtual file: a component whose first type parameter declares a default is read at it, from a file the checker holds in memory (`createSnapshot`'s `fileSystem` layer, read by tsrs and the Go beta alike) in a second snapshot made only when a requested component is generic; an instantiation that does not form keeps the structural props with the checker's error as the reason ([generic components](../type-checker-integration.md#generic-components-adr-0026-slice-s5)). Gate: `Poly<'div'>` gives at least 260 props and `'a'` differs (PASS: 281 and 289, on tsrs and the Go checker, `crates/semantic/tests/instantiate.rs`).
6. **S6** (done, one gate failed) Watch on `snapshot.update` with RSS recycling: the warm checker keeps its snapshot and brings it up to date with `updateSnapshot` (`ensurePrograms`, the files the session announced), and before an answer compares every file its program read with the stamp it had; an unannounced change answers from a fresh snapshot with a warning naming the file ([watch](../type-checker-integration.md#watch-adr-0026-slice-s6)). Gate: an unnotified edit fails a test loudly (PASS, `crates/semantic/tests/watch.rs`, on tsrs and the Go checker); Chakra edit-and-query p95 at most 25 ms (PASS at 22.6 ms for a component with props of its own in the Chakra program; FAIL at 565 ms and more for one of Chakra's `ButtonProps`, whose floor is converting its 1,140 props, 330 ms on an unchanged snapshot, while the checker's CPU per edit fell from 437 to 737 ms to 56 to 70: [gate measurements](../gate-measurements.md#watch-on-snapshotupdate-s6)); 300 Chakra edits stay under the threshold (PASS, peak 321 to 357 MiB against 768, 5 `worn` replacements, answers byte-identical to a fresh session's).
7. **S7** Delete the structural resolver for what the suite covers. Gate: every suite row passes with the fallback off on supported platforms; a Windows ARM64 job runs the fallback. (Windows was dropped as a supported platform afterwards, trail 370, so that job no longer exists.) Before any of it goes, the facts the merge took from it come from elsewhere: **S7a** (done) the checker supplies `parent`, `declarations`, tags and `composes` (gate-large: 467,019 of the 467,221 props only the checker returns carry `parent`; the other 202 are members of type literals, which have no parent by definition); **S7a2** (done) oxc's syntax supplies `defaultValue` and union member order, and the checker lane passes with the resolver's answer for them off (`--no-resolver-facts`; [defaults and union order](../type-checker-integration.md#defaults-and-union-order-adr-0026-slice-s7a2)).
8. **S8** (done, 2026-11-12) Make the checker the default (`--no-checker`, `checker: false`), and the docs. The owner flipped it on every surface, `extract` included, knowing the structural speed lead no longer describes the default: `extract` of `gate-large` takes 6.0 s and 970 MiB with the checker against 0.10 s and 200 MiB with `--no-checker` ([gate measurements](../gate-measurements.md#the-checker-is-the-default-s8)). The Vite plugin, which has no switch and serves whole outputs, and `watch` stay structural. A session's kept checker answers now share their props, which a session asking every story would otherwise have held at about 6.7 MiB per Chakra component. Gate: `just lint doc-check machete typos` (PASS), and the list below.

### Gates before the default flips

S8 stays behind these gates (status at the flip, 2026-11-12):

- The checker lane of the construct suite (caliper's checker path over `apps/oracle/construct-suite`) shows no regression against the structural path except listed improvements. **PASS**: `just test-checker-lane` on the S8 branch.
- Output is deterministic across checker counts on a large program. **PASS in its nearest form** (repeated runs, thread counts, restarts and query order; tsrs's `--api` has no checker count), on the linked checker in trail 369 slice 2 (PR 440).
- A Linux CI run of the checker path is green. **PASS**: CI's `Test / Rust` (ubuntu) runs the semantic suite on the built-in checker in every PR.
- Memory behaviour past 600 edits in a watch session, with the recycle threshold (768 MiB `max_rss_mib`) exercised. **PASS** in trail 369 slice 2 (PR 440): 650 edits, and the bound crossed stops the linked checker.
- The tsrs-against-Go parity check (`pnpm --filter caliper-docgen-oracle construct:parity`, PR 392) passes on the pinned version, and runs on every pin change. **PASS**: 235 of 235 rows identical on `tsrs` `0.23.0-ts7.1.0-beta`, none allow-listed.

The determinism and memory gates are measured by `just gate-measure`, on the linked checker since trail 369 slice 2 (both PASS in process); what it reads, and why the first gate's wording cannot be met as written (tsrs's `--api` has no checker-count option), is in [gate measurements](../gate-measurements.md). For the linked checker the memory gate's threshold is the same 768 MiB read from its arenas, and crossing it stops the checker rather than recycling it.

## Alternatives considered

- **Keep the checker opt-in.** Two sources of truth, and the default keeps the silent wrong answers above.
- **Checker for the addon only.** The CLI and agents read the same wrong types, and they can afford to wait.
- **Spawn the `tsrs` binary** (`@tsrs/<platform>` with the npm packages). Process isolation and a restart lever, but the pipe costs more than the checker (367 against 141 ms on one answer), and every platform needs a binary found or shipped.
- **Parse with `tsrs_parser` instead of oxc.** Unpublished like every tsrs crate, and the extractor is written against oxc's AST, which already gives the syntactic facts kept here at about 2 ms per incremental update.
- **Keep investing in the structural resolver.** Each defect class above re-implements a checker rule and was silent until a comparison found it.
